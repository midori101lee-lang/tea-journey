- 用户明确要求：**先出方案、确认后再写代码**。不要擅自进入编码阶段。

### 已确定的架构决策
- Core + Platform 三层：Core（纯逻辑，禁 import React/DOM）/ Shared UI / Platform Shell（web + xhs 两份薄壳）。目标 Core+Shared 占代码 ≥85%。
- 技术栈：Vite 5 + TS + React 18；小红书端构建时把 react/react-dom alias 到 `preact/compat` 以压体积。
- 状态：Zustand；样式：CSS Modules + CSS 变量 Token（不用 Tailwind）。
- 动画分工：CSS 做 UI/转场，内联 SVG 多形态图层切换做叶片形变（禁用 path morph），Canvas 2D 仅做粒子；音效用 WebAudio 合成，零音频文件。
- 美术：全部内联 SVG，MVP 不用位图，保证秒开与零图片请求。
- 存储：localStorage key `teaworld.save.v1`，经 StorageAdapter 抽象 + migrations 版本号，隐私模式降级为内存。
- **关键扩展机制**：工艺用数据驱动 `Recipe.steps: StepId[]` + `registerStep()` 注册表。未来加红茶/乌龙/泡茶/斗茶只加数据和组件，不改现有代码。
- 双端差异用 feature flag + 同一套 `params: { casual, standard }` 难度档实现，禁止散落的 `if (isXhs)`。

### 游戏设计要点
- 五步：采摘(权重15) / 摊晾(10) / 杀青(30) / 揉捻(20) / 干燥(25)，加权总分 → S/A/B/C 四级。
- 核心玩法是杀青：按住升温、松手降温的惯性指针 + 180–220℃ 安全区 + 260℃ 焦糊惩罚 + 青气条下降 + 锅内叶色四级实时演进。每一步**没有失败结局**，只有风味差异 + 一句话评语（「让用户玩懂，而不是考试」是用户明确要求）。
- 风味标签系统：每步产出 tags → 合成 2–3 个性格标签 → 随机命名「前缀·香型型茶类名」。
- MVP 只开放绿茶三型（炒青/烘青/晒青），六个大茶类槽位做收集驱动。
