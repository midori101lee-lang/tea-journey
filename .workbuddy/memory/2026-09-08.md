## 《茶游记》产品升级方案 V0.2（基于 TeaWorld v0.1 融合设计，未写代码）

产出文档：`docs/tea-journey-plan-v0.2.md`（基线为 `docs/tea-world-mvp-plan.md`）。用户要求**先出方案、确认后再编码**。

### 定位变更
- TeaWorld v0.1 = 制茶工具（制茶即本体）→ 《茶游记》= 茶山游历（制茶是进入世界的第一把钥匙）。
- 长期动力排序：探索欲 > 收集欲 > 成长欲 > 知识学习。

### 保留（v0.1 一字不改）
制茶五步骨架与全部交互、杀青控火小游戏、叶片形态演进、三层反馈、Core/UI 分离、配方数据驱动 `Recipe.steps` + `registerStep()`、双端 Preact alias、Vite+TS+React18+Zustand+CSS Modules、全内联 SVG + WebAudio 合成、StorageAdapter 与 schema 迁移、事件总线、配色 Token 与 UI 组件风格。

### 关键修改
- M1 五维数字评分 → 内部仍算分，对外只给「品质等级 + 自然语言评价 + 可售茶钱」。
- M2 制茶由「不会失败」改为**可以失败**（废品），但只消耗鲜叶（鲜叶可无限采），永不卡死。
- M3 首页大地图 → 轻量茶区地点列表（茶馆/茶园/制茶坊/茶桌/集市锁/山道锁）。
- M4 图鉴（六大茶类槽）→ 《我的茶游记》手账，按时间倒序的游记流。
- M5 今日茶签 → 「今天山里做什么茶」（由茶区 + NPC 决定）。
- M6 结果页从终点变为中点（→ 茶篓 → 泡/送 → NPC 评价 → 线索）。
- **M9（待确认）**：武夷山岩茶配方中「摊晾」替换为「做青（摇青）」——岩茶工艺是 萎凋→做青→杀青→揉捻→炭焙，没有摊晾；摊晾组件保留给未来西湖龙井。

### 新增
Region / Location / 茶区主题色（Region.theme 覆盖 CSS 变量）、NPC + Dialogue（first/repeat/conditional，按 visitCount 与 flags）+ NPC 记忆、茶篓（TeaStack 按 茶种+品质 堆叠）、茶钱、鲜叶、单一熟练度（四档文字：手生→渐入佳境→得心应手→山里有名的手艺人）、**Clue 线索系统（3 条解锁下一座山，且需玩家主动「出发」）**、声明式 UnlockCondition 条件树、TravelJournal、Comic（2–4 格）。

### MVP 范围
只做「武夷山第一日」：茶馆开场（老陈递茶）→ 茶园（阿秀，肉桂/水仙/大红袍）→ 采茶 → 制茶坊（岩伯，做青→杀青→揉捻→炭焙）→ 结果入茶篓 → 茶桌泡茶（周伯点评）→ 回茶馆（林姑娘给杭州线索 1/3）。
5 位 NPC：老陈、阿秀、岩伯、周伯、林姑娘。明确不做：多茶区、集市、斗茶、七日茶馆、云存档。

### 优先级
P0 = Core 类型 + 武夷山数据 + 玩家状态 + 制茶四步与失败机制 + 制茶坊/茶园场景 + 对话系统 + 茶馆开场 + 存储 v2。
P1 = 简化泡茶、NPC 点评分支、线索系统、茶篓 UI、手账、分享卡、小红书线性流。
P2 = 杭州/潮州等新茶区、正式漫画、中国地图、完整泡茶、集市、斗茶、七日茶馆。

## 追加：《茶游记》V0.3 真实性校准（同日，仍未写代码）

产出文档：`docs/茶游记_产品方案_V0.3.md`（22 节）。依据 `docs/茶游记_武夷山真实性资料库_V1.0.md`（含 S/A/B/C/D 来源分级与国家标准 GB/T 18745、国家级非遗资料）。

### 六处冲突校准（均按资料库来源等级裁决）
- A：「武夷岩茶没有摊晾」→ 改为「通用摊晾组件不用于武夷山，改用**倒青/萎凋**（复式萎凋·两晒两晾）」；withering 组件保留给未来绿茶。
- B：流程 `采摘→做青→杀青→揉捻→炭焙` → 改为 `采茶→倒青→做青→炒揉（双炒双揉）→焙火`。
- C：焙火「控温+含水率烘干」→ **废弃**，改为「动态火候指针 ×5 + 火功累积」。低温久烘 = 多轮稳定 > 一次爆发。
- D：采摘「只取嫩芽」→ **反转**为「开面采」（合用/太嫩/太老/损伤四类判断）。副产品：阿秀台词「你们外头做绿茶要嫩，我们这儿要开面」成为杭州伏笔。
- E：「水仙适合女性喝」→ 不采用；引入 `TeaFact(level)` vs `TeaCopy(kind)` 数据标记，防止游戏文案伪装成事实。
- F：「杀青」在武夷山一律改称「**炒青**」；StepId 用 `chaoqing`，复用 v0.1 fixation 机制；`fixation`/`withering`/`drying` 保留给未来绿茶。

### 关键设计决策
- 双炒双揉保留，但压缩为**一个 step 内两轮**（炒青→趁热揉→复炒→复揉），"趁热"用 3 秒热晕窗口表达。
- 做青是招牌：观察→摇青(力度+时长)→静置走水→判断再摇或收手；无进度条提示；单日天况（sunny/cloudy/windy-north/humid-rain）带来不可背答案的差异；**叶缘转朱砂红**是核心视觉记忆点。
- 焙火绿区动态漂移（茶种/前序表现/轮次/熟练度/随机），明确它不是专业温度模拟。
- 神品降级：取消常驻等级，改为 ≤2% 隐藏彩蛋「难得」，**不进图鉴与成就**，避免刷分心态。
- 失败必须归因：8 个 FaultTag → 可读短句（「摇得太急，叶子受伤了」）。
- 六棵母树 = 老陈闲谈 → 对话 → 手账【茶山旧闻】+ 漫画，**绝不可采**；结果页注明「此大红袍，非九龙窠那几棵」。
- 4 张漫画各有明确触发行为（做青后/采茶后/母树闲谈后/二次进茶园）。
- 架构增量（非重构）：StepId 扩 `daoqing|zuoqing|chao-rou|roasting`；新增 **StepMeta**（gameName / realProcessName / simplificationNote）把映射表写进数据；StepOutcome 加 `fault` + `visualState`；ProcessingResult 加 `faultReason` / `roastLevel` / `visuals.edgeRed`；schema 升至 v3。

### 待考证项（不阻塞开发）
