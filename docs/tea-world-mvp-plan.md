# 茶世界 · 茶文化互动小游戏 MVP 产品与技术方案

版本：v0.1（待确认）
日期：2026-09-07
范围：制茶主线 MVP + 双端（GitHub Pages / 小红书）架构

---

## 0. 一句话定义

> 一本可以玩的茶文化绘本。用户用 90–150 秒做完一捧属于自己的茶，顺手记住两句茶知识。

设计取舍的总纲：**先把「制茶」这一条线做得好玩、好看、完整**，其余模块以数据驱动的方式预留，不做推翻式重构。

# A. 产品结构

## A1. 整体信息架构

```
茶世界（根）
├── 🏡 首页：茶世界小地图（仅 Web 端存在）
│   ├── 🌱 制茶        　　← MVP 唯一开放
│   ├── 🫖 泡茶        　　🔒
│   ├── 🏮 茶集市      　　🔒
│   ├── ⚔️ 斗茶        　　🔒
│   ├── 📖 茶漫画      　　🔒
│   └── 📚 我的茶叶图鉴  　← MVP 开放（内容随进度增长）
│
└── 🌱 制茶流程（Web / 小红书共用）
    ├── 今日茶签（决定今天做什么茶）
    ├── 采摘 → 摊晾 → 杀青 → 揉捻 → 干燥
    ├── 制茶结果（茶卡）
    └── 存入图鉴 + 解锁知识卡
```

**关键设计：小红书版没有「首页地图」这一层。** 它是同一棵树的一个剪影，而不是另一棵树。

## A2. 首页布局（GitHub Pages）

竖屏优先，一张「可点的小地图」，而非菜单列表：

```
┌─────────────────────────┐
│  宣纸留白 + 竖排标题      │   ← 顶部：茶世界 · 制茶小记
│  「今天，来做一杯         │
│    属于自己的茶」         │
├─────────────────────────┤
│                         │
│   ☁ 远山淡影             │
│   🌱 茶园（可点，微动）   │   ← 主场景，中心略偏上
│   🏠 茶坊（制茶入口）     │   ← 唯一发光 + 呼吸动画
│   🏮 茶集市 🔒           │
│   ⚔ 斗茶台 🔒           │   ← 灰调 + 轻雾 + 锁
│   📖 茶书屋 🔒           │
│   🫖 茶室 🔒            │
│                         │
├─────────────────────────┤
│ 📚 我的茶叶图鉴  今日茶签 │   ← 底部两个次级入口
└─────────────────────────┘
```

要点：
- 场景是**一张整画的 SVG**，不是拼贴图；肉眼可辨的元素用一个「微微呼吸 / 摇曳」的 CSS 动画区分可交互性。
- 锁定入口点击后：轻轻晃一下 + 底部浮出小条「茶坊还在收拾，下次见」（不是弹窗，不打断）。
- 右下角常驻「我的图鉴」，让用户第一次制茶后有一条回访路径。

## A3. 模块关系

| 模块 | 依赖 | 产出 | MVP |
|---|---|---|---|
| 制茶 | 茶叶谱 · 工艺配方 | 成品茶（入图鉴） | ✅ |
| 我的图鉴 | 制茶产出 | 收集进度 · 成就感 | ✅ |
| 茶漫画 | 工序 ID → 知识卡 | 科普内容 | 接口预留 |
| 泡茶 | 图鉴中的茶 | 一杯茶的品鉴结果 | 后续 |
| 茶集市 | 图鉴 · 虚拟货币 | 新茶叶种子 → 回流到制茶 | 后续 |
| 斗茶 | 图鉴中 ≥2 款茶 | 对决结果 | 后续 |

**回流关系很重要**：集市买到「新的茶种」→ 回到制茶做新工艺 → 产出进图鉴 → 图鉴解锁斗茶。这条闭环让 MVP 制茶不是孤岛。

## A4. 制茶完整用户流程

```
[Web] 首页 → 点「茶坊」           [小红书] 首屏「开始制茶」
          ↓                                  ↓
     ┌────────────────────────────────────────┐
     │  今日茶签：抽今天的茶（MVP 三种绿茶）    │
     │  一屏说明今天做什么茶 + 工艺路线概览     │
     └────────────────────────────────────────┘
          ↓
     ① 采摘   目标 8–12 颗嫩芽         ~35s
          ↓  完成 → 「今天的鲜叶，采好了。」→ 知识卡浮标
     ② 摊晾   摊开 + 等水汽回落         ~20s
          ↓  → 「鲜叶，慢慢醒了。」
     ③ 杀青   长按控火，守住温区         ~30s（核心玩法）
          ↓  → 即时评语 → 知识卡「杀青是在杀什么？」
     ④ 揉捻   画圈施力，叶片成条         ~25s
          ↓  → 「叶片开始有了自己的形状。」
     ⑤ 干燥   控温慢烘至含水达标         ~25s
          ↓  → 知识卡「茶叶为什么一定要干燥？」
     ┌────────────────────────────────────────┐
     │  结果页：五维星级 · 等级 · 风味 · 评语   │
     │  生成竖版茶卡（可截图 / 保存图片）        │
     └────────────────────────────────────────┘
          ↓
     写入「我的茶叶图鉴」→ 显示图鉴收集进度 n/6
```

退出策略：任何步骤右上角可退出；退出即保留当前进度到草稿（localStorage），下次回到「继续制茶」。

# B. 游戏设计

## B0. 通用规则

- 五个工序统一接口：`StepResult { score: 0–100, tags: FlavorTag[], comment: string, durationMs }`
- 每一步**不会失败**——只有「表现不同 → 风味不同」。这点很重要：让用户体验是「我的茶有自己的性格」，而不是「我考砸了」。
- 每一步都有一条**兜底通道**（例如「交给老师傅」按钮），让赶时间的用户也能出结果（分数按 B 级基准）。小红书端尤其需要。
- 所有手感反馈三层：视觉（形变 + 粒子）+ 音效（WebAudio 合成）+ 触感（`navigator.vibrate`，iOS 降级为视觉）。

---

## B1. 采摘

| 项 | 设计 |
|---|---|
| 画面 | 一丛茶树占据画面 2/3，12–16 个芽点分布在枝条上；左下角竹篓 |
| 操作 | 点击单颗采摘；也支持**横向滑动连采**（连续掠过 3 颗以上触发「一扫」连采，额外加成） |
| 反馈 | 芽点在未碰时随微风轻摆（CSS keyframes）；点击 → 芽从枝头脱离 → 抛物线落入竹篓 → 篓子下沉 2px + 计数 +1 + 轻微"簌"声 |
| 变化态 | 三种芽：单芽（优）/ 一芽一叶（良）/ 老叶（差，采到会="-1 分 + 提示"「这片太老了」） |
| 成功机制 | 采满 12 颗自动结算；或用户主动点「够了」提前结束（芽不够则后续工序上限受影响） |
| 评分 | 嫩芽率 70% + 完整度 20%（是否频繁误触甩动）+ 连采效率 10% |
| 产出标签 | 嫩芽率 ≥85% → `鲜爽`；<50% → `粗老` |

## B2. 摊晾

| 项 | 设计 |
|---|---|
| 画面 | 木桌 + 竹匾；鲜叶在中央堆成一坨；右侧「水汽」竖条 + 「柔软度」竖条 |
| 操作 | 手指在竹匾上**来回拖动摊开**（像抹平一堆东西）；摊匀度实时上升。摊完后竖进入等待，用户自主决定何时「收叶」 |
| 反馈 | 叶片随拖动散开并旋转移位；水汽以轻微半透明白雾粒子上升（Canvas）；叶色从鲜亮翠绿渐变为**稍暗哑**（0–20s 渐变） |
| 成功机制 | 水汽条自然回落至目标区间（20%–40% 为最佳窗口）。停在窗口内 = 完美；过早 = 偏青；过久 = 闷味 |
| 评分 | 摊匀度 60% + 停手时机 40% |
| 产出标签 | 完美 → `通透`；过早 → `偏青`；过久 → `闷` |
| 时长 | 拖动约 8s + 等待约 12s，可用「快进」加速 |

## B3. 杀青（核心玩法）

| 项 | 设计 |
|---|---|
| 画面 | 斜置炒锅占画面中央；下方柴火；锅上方一个**竖直温度带**（绿=安全区 180–220℃ / 黄=不足 / 红=过头 260℃+）；右侧「青气」下降条 |
| 操作 | **按住**屏幕任意处 = 添柴升温；松手 = 自然降温。指针上升有惯性（约 0.8s 延迟），松开也是缓降→ 制造「控火」的手感；也支持上下滑动微调 |
| 反馈 | 火苗随温度放大 + 火星粒子飞出；锅面热气波纹；**锅内茶叶颜色实时演进**：鲜绿 → 深绿 → 油亮墨绿（完美区间）→ 出现褐点（过头）。超过 260℃ 有「噼啪」声 + 屏幕边缘微红晕 |
| 成功机制 | 青气条从 100% 降到 0 即完成。只有在安全区才降得快；低温几乎不动（逼玩家升温，制造张力）；超过危险区则累积「焦糊点」，累计 3 点后每次扣重分 |
| 失败处理 | **不中断**：焦糊只是扣分 + 画面留褐斑，最后评语「火有点猛，下次温柔一点」 |
| 评分 | 安全区停留时长 55% + 未焦糊 30% + 总时长效率 15% |
| 产出标签 | 无焦糊且高效 → `清亮`；有焦糊 ≤2 → `微火香`；≥3 → `焦苦`；青气未退净 → `青气` |

**为什么它好玩**：一个「有惯性的指针 + 双向惩罚 + 可视化后果（叶子变色）」的微型控制游戏，30 秒内讲清了「杀青要高温但不能过头」。

## B4. 揉捻

| 项 | 设计 |
|---|---|
| 画面 | 竹匾上的一团茶叶特写；中心一个淡色圆环指引；底部「力度」条（浅=不足 / 中=理想区间 / 深=过重） |
| 操作 | 手指按住，**沿圆环画圈**。系统采集 `path 速度 × 圈数`；另有一条：按压力度用**移动距离与停顿**间接表达（避免依赖 3D Touch） |
| 反馈 | 叶片随圈数逐步卷曲：`扁平 → 边缘内卷 → 半卷 → 紧细条索`，用 4 段 SVG 形态做 opacity 交叉淡入 + 轻微 rotate/scale，视觉连续；适度时有茶汁微光渗出；过重时碎屑飞出 + "咔"的脆响；指尖跟随一圈淡墨痕 |
| 成功机制 | 累积 10 圈（小红书端 6 圈）。其中「力度落在理想区间」的圈数计为有效圈 |
| 评分 | 有效圈占比 75% + 节奏稳定度（圈速方差小）25%；过重时长单独计入碎叶惩罚 |
| 产出标签 | 紧卷偏重 → `浓醇`；轻揉 → `清甜`；碎叶多 → `断碎` |

## B5. 干燥

| 项 | 设计 |
|---|---|
| 画面 | 三种任选（决定风味走向）：**炭焙**（火盆）/ **烘干**（焙笼）/ **日晒**（竹筛 + 阳光） |
| 操作 | 同上仰式控温：滑杆或直接按住升温；目标「含水率」从 ~35% 降到 ≤7%。低温慢烘品质高但耗时长（25s），高温快（12s）但易产生高火味 |
| 反馈 | 含水率以「叶片光泽 + 手感干硬度」可视化；炭焙时有细微白烟；日晒有光斑位移与暖色滤镜随时间加深 |
| 成功机制 | 含水 ≤7% 完成；过程中累计「高火时长」作为惩罚项 |
| 兜底 | 「交给时间」按钮 → 自动低温慢烘，固定产出 B+ 结果（照顾小红书「我想快点看结果」的用户） |
| 评分 | 含水达标 50% + 无高火 35% + 工艺与茶种匹配 15% |
| 产出标签 | 慢烘足 → `甘润` / `栗香`；高火 → `焦躁`；日晒 → `阳光味` |

## B6. 结果计算

**总分（加权）**

```
总分 = 采摘×0.15 + 摊晾×0.10 + 杀青×0.30 + 揉捻×0.20 + 干燥×0.25
```

**等级**

| 等级 | 分数 | 星级换算 | 评语基调 |
|---|---|---|---|
| S · 上上 | ≥ 90 | ★★★★★ | 「这泡茶，可以请人喝了。」 |
| A · 上 | 78–89 | ★★★★☆ | 「干净利落，有那么点意思。」 |
| B · 中 | 62–77 | ★★★☆☆ | 「还能喝，下次再稳一点。」 |
| C · 下 | < 62 | ★★☆☆☆ | 「火候还欠火候——不过茶是自己的。」 |

**风味合成**：每步产出的 tags 汇总 → 取权重最高的 2–3 个作为茶的性格标签。例：`鲜爽 + 清亮 + 甘润` → 「春山型」。

**随机命名**：`[季节/意象前缀] + [香型] + [茶类名]`
- 前缀池：春山、雨后、小满、南枝、晚风、初雪、竹下……
- 示例：「竹下 · 清新型绿茶」「雨后 · 浓醇型绿茶」
- 同名不重复：加编号后缀「第 003 号」

**最终呈现**：

```
        今日制茶结果
     🍃 竹下 · 清新型绿茶

     鲜叶   ★★★★☆
     杀青   ★★★★★
     揉捻   ★★★★☆
     干燥   ★★★★☆

        品质  A · 上   86 分

    香型标签： 鲜爽  清亮  甘润

   「茶香清亮，带一点春天的味道。」
```

## B7. 收集与长期动力（MVP 最小版）

- **六大茶类收集槽**：绿 / 白 / 黄 / 青(乌龙) / 红 / 黑。MVP 只解锁绿茶家族，其余显示剪影 + 「待解锁」。
- **MVP 内含 3 款可做绿茶**（低成本做出差异性，全部复用同一套五步 UI，只改配方参数与末端干燥方式）：
  1. 炒青型（锅炒杀青 + 烘干）
  2. 烘青型（杀青 + 炭焙慢烘）
  3. 晒青型（杀青 + 日晒）
- **成就（轻量）**：首次制茶 / 首次 S 级 / 集齐绿茶三型 / 连续 3 天制茶。
- **回访钩子**：今日茶签每天不同（按本地日期的种子随机），配合「今日运势签文」式文案。

# C. 视觉设计

## C1. 视觉关键词

手绘线稿 · 宣纸质地 · 朱印点缀 · 竹木原色 · 留白 · 温润不艳

## C2. 配色（Design Tokens）

| 用途 | 色值 | 说明 |
|---|---|---|
| 纸底 | `#F6F1E7` / `#FBF7EF` | 页面主底，宣纸感 |
| 墨色 | `#2E2A26` | 主文字与线稿 |
| 淡墨 | `#6B6259` | 次级文字 |
| 竹青 | `#6E8C6A` | 主辅色 |
| 嫩芽 | `#A8C58A` | 生长/进度 |
| 汤色 | `#C9A24B` | 高亮/结果 |
| 朱砂 | `#B4453A` | 印章/强调/负反馈警示 |
| 淡赭 | `#C8A98A` | 器物/木桌 |
| 茶绿（干茶） | `#4A5A3C` | 成品叶色 |

正文克制：**一屏不超过 3 个彩色 ramps**。

## C3. 字体

- 标题 / 茶名：衬线，`"Songti SC", "STSong", "Noto Serif SC", serif`
- 正文：`system-ui, "PingFang SC", sans-serif`
- 数字 / 评分：`ui-monospace`（表格感）
- 首屏标题用**竖排**：`writing-mode: vertical-rl`（新中式的关键一笔，成本极低）

## C4. 场景构成

**首页（茶世界地图）**：远山淡影 3 层（不同透明度做空气透视）+ 茶树丛 + 茶坊（带炊烟动画）+ 集市招牌 + 斗茶台 + 书屋；前景压一角竹枝作为装饰框。整体俯视约 30°，SVG 单幅绘制。

**制茶空间**：统一背景为「木桌 + 窗光 + 一角竹影」，每一工序在桌面上替换**主体器物**：
- 采摘：破例切到室外茶园（唯一的外景，制造开场感）
- 摊晾：竹匾
- 杀青：铁锅 + 灶
- 揉捻：竹匾特写 + 双手（可选）
- 干燥：炭盆 / 焙笼 / 竹筛（三选一）

> 统一地平线与光位，让五个场景像同一张桌子上的连续画面，避免"五个独立 minigame"的拼贴感。

## C5. 素材清单（全部内联 SVG，MVP 不用位图）

| 类 | 素材 |
|---|---|
| 环境 | 远山、云、竹枝、窗光、木桌纹理、宣纸纹理（CSS 生成的极淡噪点） |
| 器物 | 竹篓、竹匾、铁锅、灶、炭盆、焙笼、竹筛、盖碗（后续）、茶罐（后续） |
| 茶叶 | 单芽、一芽一叶、老叶、摊晾叶、杀青叶（4 级色）、卷曲叶（4 级形态）、干茶（3 类） |
| UI | 印章按钮、纸条标签、进度竹节条、星级（茶叶形代替五角星）、知识卡小卷轴、锁 |
| 动效元件 | 火焰（3 档）、热气、水汽、火星、光斑、指尖轨迹笔触 |

**为什么全 SVG**：无网络请求、无位图锯齿、可直接用 CSS 变量换色（同一片叶子在不同工序改一个 `fill` 即可）、总体积远小于 PNG 序列帧。小红书端尤其受益于零图片请求。

## C6. UI 组件风格

- **按钮**：仿宣纸小签条，圆角 4px，`box-shadow` 用极淡赭色偏移而非黑；按下有 1px 下沉 + 纸面微凹。
- **进度条**：不用工业感进度条，用「竹节刻度」——分段小格，随进度点亮。
- **星级**：不用 ★，用**五片小茶叶**（更符合世界观，也更容易做成品牌记忆点）。
- **弹层**：底部上滑的「纸条」，不做居中模态对话框（游戏感更强，手机更好按）。
- **分享卡**：3:4 竖版，宣纸底 + 竖排竖排茶名 + 右下朱印（印文随机："自制" / "手作" / "一味"）。
- **文字**：全部口语化短句，禁止教科书句式。例：「杀青，其实是在把叶子里那个“爱闹的酶”哄睡着。」

# D. 技术设计

## D1. 技术选型

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | **Vite 5 + TypeScript** | 多入口天然支持；对两套产物分别打包 |
| 框架 | **React 18**（小红书构建时 alias 到 `preact/compat`） | 同一份组件代码，Web 用 React (~45KB gz)，小红书用 Preact (~5KB gz)，**零重写** |
| 状态 | **Zustand** | 1KB，比 Redux 轻，比 Context 少重渲染；核心 game state 与 UI state 分离 |
| 样式 | **CSS Modules + CSS 变量 Token** | 无运行时开销，变量便于换肤；不引 Tailwind（避免类名噪音与体积） |
| 动画 | CSS（UI/转场） + 内联 SVG 形态切换（游戏主体） + Canvas（粒子：水汽/火星/光斑） | 见 D6 |
| 音效 | **WebAudio 程序合成**，零音频文件 | 「簌 / 咕叽 / 噼啪 / 水声」均可用噪声+滤波+包络合成，省几百 KB |
| 存储 | localStorage + 带版本迁移的适配层 | 见 D5 |
| 部署 | GitHub Actions → GitHub Pages（`base` 动态注入） | 小红书产物同仓不同目录，可走 CDN |

技术选型的核心理由是一个约束：**小红书端必须「秒开」**。所以不引 UI 库、不引动画库（GSAP/Framer 都不用）、不引图片资源、不引音频资源。所有动效用 CSS transform + SVG 手搓，既能控体积，也让每一处手感完全可调。

## D3. 为未来模块预留的接口

这套结构里，**加一个新模块 = 加一个 folder + 加一条 data + 注册一个组件**，不动已有代码：

```ts
// core/data/recipes.ts —— 数据驱动的工序流水线
export const greenRoasted: Recipe = {
  id: 'green_roasted',
  teaId: 'green',
  steps: ['picking', 'withering', 'fixation', 'rolling', 'drying'],
  params: { fixation: { safeBand: [180, 220], targetSeconds: 8 }, drying: { method: 'roast' } },
};

// 未来红茶：只改数组，不写新 UI
export const blackTea: Recipe = {
  id: 'black_gongfu',
  teaId: 'black',
  steps: ['picking', 'withering', 'rolling', 'fermentation', 'drying'], // ← 少了杀青，多了发酵
  ...
};
```

只要实现一个 `FermentationStep.tsx` 并 `registerStep('fermentation', ...)`，红茶就上线了。**这就是配方數據驱动的红利。**

| 未来模块 | 预留方式 |
|---|---|
| 泡茶 | `core/brew/`，同样 recipe 驱动；复用 components/art 中的盖碗、公道杯素材 |
| 茶集市 | `core/data/teas.ts` 已含 price/origin/flavor 字段；集市只是它的一个视图 |
| 斗茶 | `core/battle/`；输入为 `TeaCard[]`，与图鉴同源，直接消费已有数据 |
| 茶漫画 | 每个工序 step 携带 `knowledgeId`，MVP 返回 stub 文案，V1.1 只补 `panels` 数据 + 一个 `<ComicStrip>` 组件 |
| 成就 | `core/progress/achievements.ts` 定义规则表，由 events 总线触发，UI 只读列表 |

**避免重构的四条自律**：
1. 一切新内容先用**数据表**表达，写不出数据表的功能说明设计还不够清晰。
2. 存储 schema 带 `version` 字段 + `migrations.ts`，未来加字段不动老用户数据。
3. 所有跨模块通信走 `events.ts`（`STEP_DONE` / `TEA_FINISHED` / `UNLOCKED`），新模块订阅即可，不需改旧模块。
4. 端差异用 feature flag 裁剪，不做 `if (isXhs)` 散落各处。

## D4. 用户数据保存

```ts
// localStorage key: teaworld.save.v1
type SaveData = {
  version: 1;
  profile: { firstPlayAt: string; totalMade: number; streak: number };
  collection: TeaCard[];        // 每张茶卡完整数据，可离线渲染
  unlockedTeaIds: string[];      // 已解锁的茶种（集市购买用）
  knowledgeSeen: string[];       // 看过的知识卡
  achievements: Record<string, number>;
  draft: MakingDraft | null;     // 中途退出的半成品
};
```

- 读写一律经 `StorageAdapter` 接口，未来换云端/微信存储只替换实现。
- `try/catch` + 兜底：localStorage 不可用（隐私模式）时降级为内存存储，游戏照常能玩。
- 小红书端限制 `collection` 只保留最近 20 张，避免存储膨胀。

## D5. 动画技术分配

| 效果 | 技术 | 理由 |
|---|---|---|
| 按钮按下 / 卡片浮层 / 场景切换 | **CSS transition**（transform + opacity only） | 走合成层，60fps，零 JS |
| 茶树摇曳 / 炊烟 / 呼吸光 | **CSS keyframes on SVG** | 循环、低开销 |
| 叶片形态变化（扁平→卷条、绿→墨绿） | **SVG 多形态图层交叉淡入** | 不用 path morph（跨浏览器不可靠），用 4 个预绘形态做 opacity + scale/rotate |
| 进度竹节点亮 / 星级点亮 | CSS + SVG mask | 可做遮挡揭示效果 |
| 水汽 / 火星 / 光斑 / 茶汤漩涡 | **Canvas 2D 粒子**（一个复用 `<ParticleCanvas>`） | 粒子数量多时比 DOM 节点便宜一个量级 |
| 手势跟手反馈（轨迹、力度） | `requestAnimationFrame` + transform | 必须跟手，不能靠 CSS transition 延迟 |
| 结果卡导出 | Canvas offscreen → `toBlob` → 下载/长按保存 | 小红书端核心出口 |

性能红线：任何时刻 Canvas 粒子数 ≤ 60，DOM 动画只用 transform/opacity，`prefers-reduced-motion` 自动降级为静态。

# E. 双端方案

## E1. 三层再确认

```
        Core（茶叶谱 / 评分 / 状态机 / 存储）—— 一份，零分支
                        ↓
        Shared UI（组件 / SVG 美术 / 工序组件）—— 一份，零分支
                        ↓
        Platform Shell（路由 / 首页 / 分享 / feature flag）—— 两份，很薄
```

目标：**Core + Shared UI 占总代码 ≥85%**。

## E2. 具体差异表

| 维度 | GitHub Pages | 小红书 |
|---|---|---|
| 入口文件 | `index.html` → `main-web.tsx` | `xhs.html` → `main-xhs.tsx` |
| 首屏 | 茶世界地图 + 竖排标题 + 六个区域 | 一句话 + 「开始制茶」一颗按钮，≤10s 开局 |
| 路由 | Hash 路由（`#/making` `#/collection`） | 无路由，单一 `step` state 线性推进 |
| 运行时 | React 18 | Preact alias（`resolve.alias`） |
| 首屏 JS 预算 | ≤ 200KB gz | **≤ 120KB gz**（首屏 ≤ 60KB gz） |
| 单局时长 | 3–5 分钟，允许探索与回看 | ≤ 90 秒，每步圈数/目标数下调约 40% |
| 引导文案 | 完整叙事 + 知识卡 + 工序背景 | 每步一行提示，知识卡收成结果页一张附言签 |
| 图鉴 | 完整六类收集 + 详情 + 成就墙 | 「我的茶」列表 + 最近一张 + 进度条 |
| 导出 | 结果卡 PNG + 可选的分享链接 | **结果卡 PNG 为第一优先级**（截图传播是唯一增长路径） |
| 兜底通道 | 「交给老师傅」可选 | **默认可见**（保证人人有结果可晒） |
| 依赖外部资源 | 禁止（也要秒开） | 绝对禁止 |
| 日签 | 今日茶签（可选入口） | 今日茶签作为默认开局方式 |

## E3. 可复用清单 vs 端差异清单

**必须共用（一行都不复制）**：
茶叶谱数据 · 工艺配方 · 制茶状态机 · 五步评分函数 · 风味合成 · 随机命名 · 评语池 · 全部文案 · 五道工序的 React 组件 · 全部 SVG 美术 · 粒子/音效/手势 hooks · 结果卡渲染 · 存储适配器 · 成就规则

**允许分叉（且只有这些）**：
应用外壳与路由 · 首页 · 端级 feature flag · step 的难度参数（同一套 params: `{ casual, standard }`）· 分享出口 UI · 图鉴的展示密度

> 注意：**难度不用两套代码**，而是同一份 `params` 里两个档位（`casual` 给小红书，`standard` 给 Web）。

## E4. 构建与部署

```jsonc
// package.json scripts
"dev":          "vite",                                  // 默认 web
"dev:xhs":      "vite --mode xhs",
"build:web":    "vite build --mode web  --base=./",
"build:xhs":    "vite build --mode xhs  --base=./",
"preview:xhs":  "vite preview --mode xhs"
```

```ts

build: {
  rollupOptions: { input: { web: 'index.html', xhs: 'xhs.html' } },

resolve: isXhs
```

CI：`.github/workflows/deploy.yml`，push 到 main 即自动构建 `dist` 并发布 Pages。

## E5. 移动端适配

- 视口：`100dvh` + `viewport-fit=cover`，适配刘海与安全区。
- 手势：全部走 `pointerdown/pointermove/pointerup` + `touch-action: none`，不用鼠标事件。
- 禁止双击缩放、禁止长按选中课程内容（`user-select: none`）。
- 单手优先：主要交互区落在屏幕下 2/3；所有「确认」在底部 thumb zone。
- 竖屏为主；横屏时显示「请竖起手机喝茶」的插画提示（不做横屏适配，节省工时）。

# G. 待确认的几个决策点

进入编码前，希望你对以下四点拍板：

1. **茶卡是否可以存到云端？** MVP 建议纯 localStorage（零成本、零隐私风险），但小红书端用户换设备会丢图鉴。
2. **MVP 是否先只做绿茶三型？** 还是第一版就告诉用户「六大茶类，先在绿茶里解锁」。
