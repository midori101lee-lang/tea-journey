# 茶游记 · 九龙窠大红袍母树背景修复报告（P0）

> 任务：把「大红袍母树.jpg」真正配置为「九龙窠 / 大红袍母树」探索场景的正式背景。
> 范围：仅资源配置 / 场景引用修复。不动 NPC 人设、对话文本、制茶 / 泡茶 / 采茶玩法、茶集市、UI 布局。

## 1. 问题根因（为何之前「背景没配进去」）

九龙窠场景在代码里**确实存在**，资源也**已经转好并放在 assets**，但玩家实际进入时渲染的却是**老陈茶馆**背景，而不是大红袍母树。根因是一条数据解析链路的分支：

- 母树对话 `laochen_mothertree`（`src/core/data/dialogues.ts`）只写了 `scene: 'mothertree'`，**没有写 `sceneArt`**。
- `NpcDialog` 计算背景用的 key 是：
  `sceneArt = dialogue.sceneArt ?? npc.sceneArt`
  因为该对话没写 `sceneArt`，就回退到 NPC 老陈的默认 `sceneArt = 'teahouse'`。
- 于是 `NpcStage` 收到的 `sceneKey` 是 `'teahouse'`，渲染的是**茶馆位图**（老陈茶馆.webp），不是母树图。

所以「大红袍母树.jpg 没配进场景」的真实原因是：**场景 key 在对话层被回退成了 teahouse，母树的 `bg` 引用从未被走到**——图片在 assets、也在注册表，但对话这条入口没指过去。

## 2. 修复内容（最小改动）

仅一處数据改动，把母树对话显式指到母树场景图：

`src/core/data/dialogues.ts` — `laochen_mothertree` 增加：
```ts
sceneArt: 'mothertree', // 显式绑定九龙窠大红袍母树背景，避免回退到老陈默认茶馆图
```

修复后链路（已确认引用闭环）：
```
WebApp: go('mothertree')
  → <NpcDialog scene="mothertree" npcId="laochen">
    → 找到对话 laochen_mothertree（sceneArt 现 = 'mothertree'）
      → <NpcStage sceneKey="mothertree">
        → SCENES['mothertree'].bg = 'assets/scenes/mothertree.webp'
          → <img class="npc-scene-bg" src={BASE_URL + 'assets/scenes/mothertree.webp'}>
            → 透明立绘层 NpcPortrait(id='laochen') 叠加其上
```

## 6. 旧占位背景检查

- `MotherTreeScene.tsx`（SVG 灰岩崖壁）仍是 `mothertree` 的 `Component` 注册项，但**仅作为 `bg` 缺失时的回退**。`NpcStage` 逻辑为 `bg ? <img> : <Scene>`，`bg` 存在时 SVG 不会渲染。故进入九龙窠后显示的是位图背景，不是 SVG 占位图。

## 7. 关于「岩伯」的说明（重要，需你拍板）

你给的目标结构里九龙窠是**岩伯**站在母树前。但现有游戏流程中，母树对话由**老陈（laochen）**主讲（`laochen_mothertree`，对话文本与漫画解锁均归属老陈），且 `recurring: true` 的贯穿设定里老陈负责「把玩家从茶馆引向茶山 / 母树」。

因此本次按「**不修改对话内容**」的硬约束：
- 九龙窠叠加的透明立绘 = **老陈.webp**（当前对话归属者），背景 = 母树.webp。背景与人物已正确分离。
- 若你希望九龙窠改由**岩伯**主讲（把 `laochen_mothertree` 的 `npcId` 改为 `yanbo`，并对齐岩伯的 `sceneArt='workshop'`→需再加 `sceneArt:'mothertree'`），这属于**对话归属 / 内容改动**，超出本次「仅修资源配置」范围，需你单独授权后再做。

> 项目 NPC 分类中岩伯确实是「岩茶 / 九龙窠 / 母树」负责人，所以把母树讲解权从老陈换给岩伯在设定上是自洽的——只是它动了对话，不在本次任务内。
