# 1. 产品定位

> **《茶游记》是一场可以玩的中国茶山游历。**
> 中国每一座茶山，都有自己的故事。

玩家是一名进入中国茶世界的**茶山游历者**。从一间茶馆开始，认识当地人，采茶、做茶、焙火、泡茶、听闲话，然后在某句话里听说——原来那边也产茶。

三句定位补充（V0.3 新增，由资料库第 20 节推导）：

- **《茶游记》不是茶知识学习工具，也不是专业制茶模拟器。**
- **真实世界决定规则，游戏机制负责降低复杂度。**（资料库 1.1）
- 玩家离开武夷山时应该想的是：「原来武夷山的茶是这么做出来的」→ 接着变成「杭州的茶是不是又完全不一样？」

# 3. 武夷山真实性校准

## 3.1 冲突处理记录

> 规则：V0.2 与资料库冲突时，先标【需要校准】，再按资料库来源等级判定，最后给出采用版本与理由。

### 【需要校准 A】「武夷岩茶没有摊晾这一步」

- V0.2 原文：武夷山岩茶配方中「摊晾」被替换为「做青（摇青）」，理由是没有摊晾这一步。
- 资料库意见（A 级，国家级非遗）：武夷岩茶传统技艺强调**复式萎凋**，非遗资料提到「两晒两晾」的做法；并明确指出「不要只写摊晾」，应使用**倒青**。
- **采用版本**：**采纳资料库。**
  1. 表述更正为：**原 TeaWorld 通用「摊晾」组件不直接用于武夷山**；武夷山第一章改用具有地方工艺语境的「**倒青 / 萎凋**」机制。
  2. `withering`（摊晾）组件**保留在组件库**，未来做西湖龙井等茶类时继续挂载，不做任何删除。
  3. 新增 `daoqing` step；`zuoqing`（做青）作为独立 step 与之并列——**倒青与做青是两件事，不是一回事**。
- 理由：V0.2 的否定式表述（"没有摊晾"）在茶文化上是危险且不必要的；资料库给出了更准确的正面表述（复式萎凋 / 两晒两晾），且来源等级更高。

### 【需要校准 B】「采摘 → 做青 → 杀青 → 揉捻 → 炭焙」

- V0.2 流程把双炒双揉、初焙全部省略，且用「杀青」「炭焙」两个通用词。
- 资料库（A 级）：非遗明确将「**双炒双揉**」列为武夷岩茶重要工艺；传统流程还有初焙、复焙/吃火/补火；焙火强调「**低温久烘**」。
- **采用版本**：见第 4、5 节。要点：
  - 「杀青」在武夷山语境下一律改称「**炒青**」（用户 V0.3-五，资料库第 6 节）
  - 「炭焙」改称「**焙火**」，玩法从"控温烘干"改为"动态火候指针"
  - 「双炒双揉」**保留**，但压缩为一个 step 内的两轮，不拆成四个关卡

### 【需要校准 C】焙火玩法

- V0.2：控温慢烘 + 含水率达标（沿用 TeaWorld v0.1 的 drying）。
- 资料库（A 级）：**焙火 ≠ 普通烘干**，传统技艺强调低温久烘；明确禁止「温度越高 → 分数越高」。
- **采用版本**：**废弃** V0.2 的含水率烘干思路，替换为「**动态火候指针 + 多轮累积火功**」（第 9 节）。
  - 「低温久烘」被翻译为游戏机制：**不是一次定生死，而是多轮稳定累积**。急火可以快，但会累积火气。

### 【需要校准 D】采摘目标「只取嫩芽」

- TeaWorld v0.1 / V0.2：采摘的核心判断是「嫩芽率」，采老叶扣分。
- 资料库（A/B 级）：武夷岩茶强调**适时采摘与鲜叶质量**，资料库第 3.2 节明确要求做成"判断什么茶青可以采"。经 **C7 裁决**，游戏内采**三类**：**合适（中开面）/ 太嫩 / 太老**（去掉"损伤叶"）。实现细节以《茶游记_采茶玩法重构方案_V1.0》为准。
- **采用版本**：V0.3 采茶改为「**开面采**」判断——岩茶要的是**中开面的成熟叶**，不是绿茶那种嫩芽。
  - 这不只是工艺修正，它成了**一条叙事资产**：阿秀会说「你们外头做绿茶要嫩，我们这儿要开面。」
  - 这一句同时埋下了杭州（龙井）的伏笔——同一个动作，在另一座山答案完全相反。这是"每一座茶山都有自己的故事"最具体的一次落地。

### 【需要校准 E】「水仙适合女性喝」

- **不采用**。资料库第 8.2、16 节明确：缺乏足够专业依据，不作为事实。
- 允许的表达：「水仙的风格和肉桂不太一样。」并**在数据层标记为 `gameCopy` / `npcOpinion` 而非 `knowledge`**（第 10 节）。

### 【需要校准 F】「所有茶都用同一套五步流程」

- 资料库第 16 节列为不采用设定。→ 架构上继续由 `Recipe.steps` 保证，V0.3 进一步让每个 step 携带 `realProcessName` 与 `simplificationNote`（第 18 节），从数据层面杜绝"一套流程套所有茶"。

# 4. 现实工艺 → 游戏工序映射

> 现实工艺的完整环节：采摘 → 倒青/萎凋 → 做青（晾青·摇青·静置反复）→ 初炒 → 初揉 → 复炒 → 复揉 → 初焙 → 扬簸 → 凉索 → 拣剔 → 复焙 → 吃火 → 团包 → 补火 → 装箱。
> 玩家**不操作全部工序**。

| 现实工艺 | 游戏是否保留 | 游戏名称 | 游戏化方式 | 为什么这样简化 |
|---|---|---|---|---|
| 采摘 | ✅ 保留 | **采茶** | **观察茶梢 → 判断是否适合采 → 采摘 → 收入竹篮 → 完成本轮鲜叶**。武夷山第一章以「**开面采**」为现实依据；茶梢分 太嫩 / 中开面 / 偏老，靠**芽叶关系与叶片形态**判断（不以颜色当答案）；结果用**自然语言反馈**，不做复杂数值评分。**实现以《茶游记_采茶玩法重构方案_V1.0》为准** | 采茶是制茶的第一环：产出「本轮鲜叶」的隐藏品质档，轻量影响后续制茶容错；并埋下"开面采 vs 嫩芽采"的跨茶区伏笔 |
| 倒青 / 萎凋（复式萎凋、两晒两晾） | ✅ 保留 | **倒青** | 铺开茶青 → 晒/晾切换（两轮）→ 观察叶态与青气判断何时收 | 复式萎凋的核心是"晒晾交替"，这本身就是一个天然的小机制，不需要发明 |
| 做青（晾青↔摇青↔静置） | ✅ **重点** | **做青** | 3–4 轮：观察 → 摇青（力度+时长）→ 静置走水 → 判断再摇或收手 | 这是岩茶灵魂，也是全章最有辨识度的玩法（第 6 节） |
| 初炒（炒青） | ✅ 保留 | **炒青** | 惯性指针控火（复用 v0.1 fixation 手感），短时 | 见第 7 节：复用机制，改名称与文案 |
| 初揉 | ✅ 保留 | **（趁热）揉捻** | 画圈成条，紧接炒青之后 | 「趁热揉」是真实要求，用"上一秒的锅气还在"的视觉连贯性表达 |
| 复炒 | ✅ 保留 | **复炒** | 同 step 第二轮，火候窗口更窄更快 | 双炒双揉是非遗明确术语，必须让玩家"做两次" |
| 复揉 | ✅ 保留 | **复揉** | 同 step 第二轮，目标从"成条"变为"紧结" | 同上 |
| 初焙 | ⚠️ 合并 | （并入焙火第一轮） | — | 初焙与复焙在玩家感知上都是"焙"，拆开只会拉长流程 |
| 扬簸 / 凉索 | ❌ 不保留 | — | 结果页一句带过（岩伯："扬一扬，晾一晾。"） | 无交互价值，但用一句话保留它的存在感 |
| 拣剔 | ❌ MVP 不做 | — | 保留为 P2 的轻量"挑拣"动画 | 资料库建议：后期可做整理/收获动画，不必成为核心操作 |
| 复焙 / 吃火 / 补火 | ✅ 保留为机制 | **焙火** | 动态指针多轮累积，后面几轮即"吃火" | **关键判断**：低温久烘 = 多轮稳定累积，正好对应"复焙吃火"的现实逻辑 |
| 团包 / 装箱 | ❌ 不保留 | — | 结果页"装入茶罐"动画 | 无交互价值 |

## 4.1 哪些工序最值得玩家"亲手做"

按「辨识度 × 可玩性 × 因果清晰度」排序：

| 排名 | 工序 | 理由 |
|---|---|---|
| 🥇 1 | **做青** | "看青做青"是岩茶独有的思维方式；叶缘转朱砂红是极强的视觉记忆点；交互天然（摇 + 等 + 看） |
| 🥈 2 | **焙火** | "低温久烘"本身就是一套游戏机制（多轮稳定 > 一次爆发）；动态指针手感好、可复用 |
| 🥉 3 | **炒青 + 揉捻（双炒双揉）** | 「双炒双揉」是非遗名片级术语；"趁热"制造节奏压力；复用已验证的控火与画圈手感 |
| 4 | **倒青** | 两晒两晾的往复有节奏感，但深度有限，控制在 20 秒内 |
| 5 | **采茶** | 重要的是"观察与判断"（看茶梢的芽叶关系、叶片大小、张开度），不是"点得快"；它是制茶的第一环，直接开启本轮鲜叶 |

**坚决不加**：扬簸、凉索、拣剔、团包、装箱。它们的正确位置是**结果页的一句旁白或一段动画**，不是关卡。

# 5. 武夷山最终制茶流程

## 5.1 玩家实际操作（5 个节点）

```text
① 采茶        ~30s   观察茶梢，开面采（详见《采茶玩法重构方案 V1.0》）
      ↓
② 倒青        ~20s   铺开 · 两晒两晾 · 判断收叶
      ↓
③ 做青        ~60s   ★ 观察 → 摇青 → 静置 → 再判断（3–4 轮）
      ↓
④ 炒揉        ~45s   炒青 → 趁热揉捻 → 复炒 → 复揉（双炒双揉）
      ↓
⑤ 焙火        ~35s   ★ 动态火候指针，多轮累积火功
      ↓
   成茶 → 结果 → 茶篓
```

单局约 **3 分 10 秒**（standard）／约 **100 秒**（casual，轮次与时长下调）。

## 5.2 与资料库推荐流程的对应关系

资料库 3.1 推荐：

```text
采茶 → 倒青/萎凋 → 做青 → 炒青+初揉 → 复炒+复揉 → 初焙 → 焙火 → 成茶
```

V0.3 的差异只有一处：**把「初焙」并入「焙火」的第一轮**，其余完全一致。理由：玩家无法感知"第一次焙"和"后面几次焙"的本质区别，但**能感知"焙了很多次、要一直稳住"**——而后者恰恰就是"低温久烘"的游戏化表达。

```ts
// core/data/recipes.ts
export const yanchaWuyi: ProcessingRecipe = {
  id: 'yancha_wuyi',
  regionId: 'wuyishan',
  appliesTo: ['rougui', 'shuixian', 'dahongpao'],
  steps: ['picking', 'daoqing', 'zuoqing', 'chao-rou', 'roasting'],
  //                                        ↑ 一个 step 内含 炒青→揉捻→复炒→复揉 两轮
  displayNote: '本流程取自武夷岩茶传统工艺中最具辨识度的节点，非完整工艺。',
};
```

# 6. 做青小游戏设计

## 6.1 设计目标

> 让玩家逐渐形成一个感觉：**我要看茶，而不是照着攻略点按钮。**

## 6.2 核心机制

```text
        ┌──── 观察 ────┐
        ↓              │
     摇青              │
   （力度 + 时长）      │
        ↓              │
     静置 / 走水        │
        ↓              │
     观察变化 ─────────┘
        ↓
   再摇一轮？还是就到这儿？  ← 玩家判断，没有标准答案提示
```

## 6.3 玩家看到的三个状态（不用数字）

| 状态 | 视觉表现 | 文字反馈 |
|---|---|---|
| **叶态** | 叶片从挺立 → 微软 → 柔软下垂 | 「叶子还挺着。」→「叶子软下来了。」 |
| **青气** | 一缕青色雾气，从浓到淡 | 「青气还重。」→「青气退了一些。」 |
| **叶缘** | 叶尖到叶缘逐渐渗出**朱砂红**（做青的标志） | 「叶缘还没动静。」→「叶缘开始有变化了。」→「红边出来了。」 |

## 6.4 操作

**摇青**：在水筛上**按住并画圈**（复用揉捻的画圈识别），圈速 = 摇青力度，持续时长 = 摇青时长。
- 有一条力度带：轻 / 合适 / 急
- 摇得太急 → 叶张破损，出现褐色伤斑（**死青**，不可恢复）
- 摇得太轻或太短 → 走水不足，青气不散

**静置**：松手后进入走水阶段，叶片状态自行演变（约 4 秒，可点击加速）。
- 静置太久不摇 → 积水，出现"闷"的负反馈

**判断**：每轮结束后玩家自选「**再摇一轮**」或「**就到这儿**」。
- 没有进度条告诉你"还差一轮"
- 但岩伯会在旁边说半句话（见 12.4）

## 6.5 不能背答案（"看天做青"）

每次进入做青，系统给出一个**当天的天况**，它影响走水速度与最佳摇青力度：

```ts
type ZuoqingWeather = 'sunny' | 'cloudy' | 'windy-north' | 'humid-rain';
// 例：'windy-north' → 走水快，宜轻摇、宜早收
//     'humid-rain'  → 走水慢，宜重摇、多一轮
```

天况以**画面 + 一句话**呈现（窗外天色变化 / 阿秀的声音："今天有北风。"），不给参数、不给攻略。
天况 + 茶种 + 采茶表现 → 每局的最佳策略都略有不同。

## 6.6 输出

```ts
ZuoqingOutcome {
  rounds: number;
  edgeRed: 0..1;          // 叶缘红边程度（决定视觉与"岩韵"倾向）
  greenNote: 0..1;        // 残余青气
  damage: 0..1;           // 叶张破损
  fault?: 'zuoqing_hasty' | 'zuoqing_light' | 'zuoqing_stale';
}
```

| 结果 | 条件 | 玩家看到的 |
|---|---|---|
| 好 | 红边适度、青气退、无破损 | 「红边出来了，青气也退了。」 |
| 偏轻 | 摇青不足 | 「青气还在里头。」 |
| 过急 | 破损 > 阈值 | 「摇得太急，叶子受伤了。」（画面出现褐斑） |
| 积水 | 静置过久 | 「捂得有点久，闷住了。」 |

# 7. 炒青小游戏设计

## 7.1 名称校准

> **在武夷山，这一步叫「炒青」，不叫「杀青」。**

- UI 文案、NPC 台词、知识卡、数据配置一律使用「炒青 / 复炒」
- 代码：**复用 v0.1 已验证的控火机制**（惯性指针 + 安全区 + 焦糊），但 StepId 用 `chaoqing`
- 旧的 `fixation` 作为**通用杀青** step 保留在库中，未来给西湖龙井等茶类使用
- 实现上：`registerStep('chaoqing', FixationLikeGame)`，两者共用同一个组件与手感，只是 params 与 copy 不同

## 7.2 玩法（沿用已验证设计，仅调参）

| 项 | 设计 |
|---|---|
| 操作 | 按住 = 升温，松手 = 自然降温；指针有约 0.8s 惯性 |
| 目标 | 让"青气"退尽，同时不产生焦糊 |
| 反馈 | 锅内叶色：鲜绿 → 深绿 → 油亮；过头 → 褐斑 + 「噼啪」 |
| 时长 | 首炒 ~14s，复炒 ~10s（更急） |
| 差异 | 复炒时窗口更窄、降温更快 → 体现"第二道火更难拿捏" |

## 7.3 与揉捻的连接（趁热）

炒青结束的瞬间不清屏，直接进入揉捻，**画面保留锅气的余温**（一层淡橙色的热晕在 3 秒内褪去）。
- 这 3 秒内开始揉捻 → 额外加成，旁白：「趁热。」
- 拖过 3 秒 → 无加成，岩伯：「凉了就不好揉了。」

> 「趁热揉捻」是资料库明确提到的真实要求，用一个 3 秒的视觉窗口表达它，比写一行说明有效得多。

# 9. 焙火动态指针设计

## 9.1 为什么废弃旧方案

V0.2 的「控温慢烘 + 含水率达标」= 把焙火做成了**烘干**。资料库第 7 节明确：焙火 ≠ 普通烘干，且禁止「温度越高 → 分数越高」。

## 9.2 玩法：动态火候指针 + 多轮累积

```
        弱火            合适             急火
      |---------------[ 🟢 ]---------------|
                        ↑
                      指针（持续左右摆动）
```

- 指针**持续左右摆动**，速度随轮次与茶种变化
- 玩家在合适时机**点击**，让指针停下
- **共 5 次点击**（对应"低温久烘"的多次补足，前 2 轮=初焙，后 3 轮=复焙/吃火）

**单次判定**

| 落点 | 结果 | 反馈 |
|---|---|---|
| 绿区中心 | 火候很稳 | 「火候走得稳。」 |
| 绿区边缘 | 基本合适 | 「这一下，还行。」 |
| 黄区 | 偏急 / 偏弱 | 「火有些急了。」/「火没跟上。」 |
| 红区 | 明显失误 | 「这一下，冲了。」 |

## 9.3 绿区必须动态变化（重要）

> **绿区不是现实世界的固定专业温度区间，它是对"火候判断"这一复杂经验的游戏化表达。**

绿区的**中心位置与宽度**随以下因素轻微漂移，玩家不能背答案：

| 因素 | 影响 |
|---|---|
| 茶种 | 肉桂吃火、水仙忌急火、大红袍窗口居中 |
| 前面工序表现 | 做青偏轻（含水高）→ 绿区左移（宜缓）；做青过头 → 绿区右移但更窄 |
| 轮次 | 越往后越窄（越焙到后面越难拿捏） |
| 熟练度 | 熟练度高 → 绿区略宽（容错提升） |
| 平台难度 | casual 模式绿区显著更宽、摆动更慢 |
| 随机 | 每局 ±小幅漂移（模拟"看茶焙火"） |

## 9.4 累积结果：火功

```ts
RoastOutcome {
  taps: TapResult[];        // 5 次
  stability: number;        // 稳定度（多次落在中心 vs 忽左忽右）
  haste: number;            // 火气累积（偏急次数）
  roastLevel: '轻火' | '中火' | '足火';
  fault?: 'roast_hasty' | 'roast_over';
}
```

- **稳定度**决定品质：**5 次都稳 > 1 次完美 + 4 次乱**。这就是"低温久烘"的机制化表达。
- 火气累积过高 → 「火气压住了茶」，香气被盖住。
- 火功等级（`轻火/中火/足火`）会写进茶卡，并且**不同茶种有各自更合适的火功**——这是差异化的隐藏维度，不提示玩家求解。
- ⚠️ **火功的定性（V1.0 收口）**：火功是**本次游戏过程形成的结果标签**，不代表对现实茶叶品质的绝对判断。**不存在「上品+足火 > 上品+轻火」的等级关系**——UI、文案、数据都不得暗示火功越高越好。

## 9.5 参数结构（支持茶种 / 熟练度 / 双平台）

```ts
interface RoastParams {
  taps: number;                       // 点击次数（standard 5 / casual 3）
  swing: { speed: number; easing: 'linear' | 'accel'; };
  band: {
    centerBase: number;               // 0..1
    widthBase: number;                // 0..1
    driftByTea: Partial<Record<TeaId, { center?: number; width?: number }>>;
    driftByStep?: number;             // 每轮收窄量
    randomDrift: number;              // 每局随机漂移幅度
  };
  toleranceByProficiency: [number, number];  // [初学, 老练] 对应的额外宽度
  carryOver: {
    fromZuoqing: boolean;             // 做青结果是否影响绿区（true）
    fromChaoRou: boolean;             // 炒揉结果是否影响绿区（true）
  };
  hasteThreshold: number;             // 火气累积上限
}
```

# 11. 六棵母树：轻量呈现设计

**原则**：它是**故事**，不是**可采资源**。绝不出现"去九龙窠采母树"的可交互入口。

**呈现路径（三步，全部为叙事）**

```
① 触发：在茶馆累计闲谈 2 次以上，或做出第一份大红袍后
      ↓
② 对话：老陈
   「你问真正那几棵？早不让采了。」
   「九龙窠那几棵，现在是看着的，不是采的。」
   「你要喝的大红袍，跟它们是两回事——这话说起来长。」
      ↓
③ 手账解锁：
   【武夷山 · 茶山旧闻】九龙窠
   （一段 3–5 句的短记，配合漫画《九龙窠那几棵》）
```

**必须守住的两条**（资料库 8.3）：
1. **母树大红袍 ≠ 今天市场上所有"大红袍"的简单来源。**
2. 玩家在茶园中采摘的"大红袍"是**商品茶品类**，与母树无关——这一点在玩家**做出大红袍**的结果页上用一句轻描淡写的话说明：「此大红袍，非九龙窠那几棵。」

**明确不做**：母树坐标、母树可点击、母树采集、母树作为稀有掉落。

# 15. 失败与品质系统

## 15.1 品质等级

> 「失败」是**正式的结果等级**，不是「废品」这种物品/知识分类。全项目只存在"失败"一个概念，不允许"品质：失败 / 物品类型：废品"并存。

| 等级 | 前台显示 | 说明 |
|---|---|---|
| 失败 | **失败** | 可理解的原因 + 极低售价（2–5 茶钱） |
| 普通 | **普通** | 「能喝」 |
| 良好 | **良好** | 「做得不错」 |
| 上品 | **上品** | 「值得拿出去待客」 |
| ~~神品~~ | ~~难得~~ | **已取消**（决策 Q2，见 15.4 保留为历史记录） |

## 15.2 失败必须有可理解的原因（不是"分数低"）

| FaultTag | 触发 | 玩家看到的原因 |
|---|---|---|
| `zuoqing_hasty` | 做青摇青过急 | 「摇得太急，叶子受伤了。」 |
| `zuoqing_light` | 做青不足 | 「青气还在里头。」 |
| `zuoqing_stale` | 静置过久 | 「捂得有点久，闷住了。」 |
| `chaoqing_under` | 炒青火候不足 | 「火没到，青气压不住。」 |
| `chaoqing_over` | 炒青过火 | 「锅太热，边上有焦了。」 |
| `rolling_broken` | 揉捻过重 | 「揉得太重，条索断了。」 |
| `roast_hasty` | 焙火偏急累积 | 「火太急，香还没转出来。」 |
| `roast_over` | 焙火过头 | 「焙过头了，火气压住了茶。」 |

结果页**只说一个最主要的原因**（不罗列），措辞是岩伯式的短句。

## 15.3 失败不阻断

- 消耗：**本轮鲜叶**（本轮采得的那一篓，用于本轮制作并被消耗；制茶结束即结束生命周期）
- 不加茶钱惩罚（决策 Q3 修订：**失败不扣茶钱**）
- **失败也出成茶**：产出「失败」等级成茶，进入茶叶记录 / 背包（可自泡、可留记录，茶钱 2–5，暂不适合斗茶）
- **想重新制茶**：回茶山找阿秀，再采一篓新的本轮鲜叶（**不回退鲜叶**）
- 失败也涨熟练度（+1），做成 +3，上品额外 +2

> **V1.1 修订**：鲜叶不是长期资源。制茶消耗的是「本轮鲜叶」这一批原材料，**不存在"鲜叶 −1"的长期资源扣除逻辑**。无论最终制成高品质茶、普通茶还是失败茶，本轮鲜叶都会结束生命周期。

## 15.4 关于「神品」（已取消，决策 Q2）

> **最终决定（2026-09-08）：取消"神品"等级，MVP 不加入任何彩蛋级。**

理由：任何"可见的最高等级"都会制造刷分心态，与"游历"定位冲突。品质仅四档（失败 / 普通 / 良好 / 上品），上品即玩家能稳定追求的最高目标。

本节保留为历史记录，供后续版本评估是否以"意外事件"而非"等级"形式轻量回归（如某次全工序无 fault 时的一句闲话），但**不进入图鉴、不进入成就、不显示概率**。

## 15.5 结果页最终形态

```
      【武夷岩茶 · 肉桂】

            上 品

   火候走得稳，桂皮香已经出来了。

        可售：38 茶钱
        火功：中火

      🎒 已收入茶篓
```

> **火功说明**：结果页的「火功：轻火 / 中火 / 足火」是**本次游戏过程形成的结果标签**，反映本局焙火走向，不代表对现实茶叶品质的绝对判断，也不形成「足火 > 轻火」的等级关系。不同茶种有各自更合适的火功，但这是差异化表现，不是优劣排序。

# 22. 最终建议

1. **先按 V0.3 的 P0 开工，不要等所有考证完成。** 待考证项（R1–R7）影响的都是文案层，而文案层是数据驱动的，随时可改，不阻塞结构开发。

2. **把「做青」当作这一章的招牌。** 如果时间只够做好一件事，就做做青——叶缘转朱砂红那一瞬间，是玩家会截图发小红书的画面。

3. **焙火的机制必须体现"稳"而不是"准"。** 五次点击都稳 > 一次完美。这是"低温久烘"唯一诚实也唯一好玩的翻译方式。

4. **岩伯的话永远只描述他看到的状态，不告诉玩家该怎么做。** 这是整个 NPC 系统能否"活起来"的分水岭。

5. **守住 P2 的边界。** 拣剔、扬簸、完整天气、四段式双炒双揉——每一个都"更真实"，每一个都会拖垮 MVP。真实，但好玩。

## 23.1 考证原则（长期有效，约束后续所有开发）

> **R1–R7 不要为了考证而考证。**
> 只优先确认会影响 **MVP 游戏机制、基础科普准确性和玩家理解** 的内容；
> 对于不影响玩法的专业细节，先采用**自然、保守、不绝对化**的表达，**不阻塞开发**。

执行口径：
- 影响机制或科普准确性的 → 开发前确认（如开面采、做青因果、低温久烘）
- 纯专业细节（投茶克数、出汤秒数、品种谱系）→ 游戏内不出现数字，用视觉与口语表达
- 一切待考证项不进 `knowledge` 数据，最多以 `npcOpinion` 口语出现
