# 《茶游记》XHS 版 · 分享机制与难度一致性 · 阶段性开发报告

> 日期：2026-09-12
> 范围：在 P0（XhsApp 复用 Web 全量流程）基础上，落实补充要求「一~十二」：保持与 Web 版一致的规则/难度、增加「分享成为游戏循环一部分」、成功发帖 +20 茶钱（防刷）、平台回调限制处理。
> 性质：**本报告为阶段性设计 + 现状盘点报告**（非实现交付）。实现待确认后进入 P1。

---

## 0. 补充要求提炼（一~十二）

- **一、二（难度/玩法一致）**：XHS 与 Web 用同一套规则、制茶/泡茶/评价/随机/失败/茶席/NPC/探索/剧情/消耗/背包/日志；只做移动端 UI、操作方式、节奏、平台能力适配，不重做简化版。
- **三、四、五（三个分享节点）**：制茶结果、泡茶结果、茶席——各自一张可分享卡。
- **六、七（奖励 + 防刷）**：成功发布一条《茶游记》相关帖子 → +20 茶钱；每种分享类型**每天首次**成功发帖才奖励，一天最多 60 茶钱；优先复用现有机制（经盘点暂无，需新建）。
- **八（平台限制）**：当前 webview 无法可靠确认「成功发帖」→ 先做分享入口+卡片、预留奖励接口、**不伪造**、报告说明限制。
- **九、十（不阻断流程）**：分享是额外奖励玩法，可跳过，不能卡流程。
- **十一、十二（最终循环/原则）**：分享叠在游戏循环之外；XHS 相对 Web 的最大新增价值 =「玩完→生成内容→分享到小红书→得茶钱→回游戏」。

## 1. 现状盘点（只读）

### 1.1 一/二原则：规则与玩法已 100% 一致 ✅，但「难度档」存在冲突 ⚠️
- XHS `XhsApp` 直接挂载 `WebApp`，制茶/泡茶/评价/随机/失败/茶席/NPC/探索/剧情/消耗/背包/日志**全部复用 Web 同一份代码与数据**，无 XHS 专属简化逻辑。这一条满足「与 Web 基本一致」。
- **⚠️ 需修正：P0「强制 `casual`」与「不降低难度」冲突。** 代码盘点证实 `casual` 并非「移动端档」而确实是**更简单的档**：
  - `PickingStep.tsx:77` 采茶容错 `tolerance -= (casual ? 0.1 : 0)`（casual 更宽容 0.1）；
  - `scoring.ts:143` 每步评分 `casualNudge = casual ? 5 : 0`（casual 每步 +5 分）；
  - 制茶多步 `if (casual) score += 5`（倒青/做青/发酵/焙火/揉捻/干燥/理条均 +5）；
  - `BrewingFlow.tsx` 泡茶温杯/注水推进更快、出汤 `rate × 0.82`（casual 更慢更易命中）。
  - Web 版默认难度是 `standard`（`gameStore.ts:175`）。**XHS 强制 casual = 比 Web 默认 standard 更简单**，违反「一、二」中「不主动降低/不提高容错」。
  - **建议修正（待你拍板）**：XHS 改回 `standard`（与 Web 默认完全一致），或移除「强制 casual」改为默认 standard 且不弹难度选择。standard 在移动端完全可玩（仅容错/节奏更紧），不破坏 UI 适配。
  - 注：P0 中为解锁「玲姨玻璃杯→杭州茶席」而去掉的 `iron_palm` 的 `standard` 绑死仍可保留（该改动只是移除了多余门禁，与难度档无关）。

### 1.2 分享 / 奖励现状
- **货币系统已具备**：`gameStore.addCoins(n)` 存在（`Math.max(0, coins+n)`），茶钱为全局唯一货币——+20 可直接复用，无需新货币。
- **平台分享入口：无。** `ResultView`（制茶结果页）当前只有「带去茶桌泡一杯/再做一锅/看看茶游记/回茶地图」，**无分享按钮**；茶席 `TeaSeatView` 的 `shareWith` 是「与 NPC 分茶喝」之意，与平台分享无关；泡茶结果在茶桌 `zhouBoAdvice` 区展示，也无分享入口。
- **分享奖励机制：无。** 需求七「若已有更合适机制则优先复用」——经盘点**不存在**，需新建（见 §2.3）。
- **可截图结果卡：P0 仅做到「页面本身可截图」，未做结构化分享卡与分享动作**。

### 1.3 三~十一数据可用性（全部可复用现有数据，无需新建评价系统）
| 分享节点 | 可复用字段（现有来源） |

## 2. 设计：分享系统（三~十一）

### 2.1 三个分享节点（不阻断流程，九/十）
每个节点在现有结果/收尾页**并列追加**一个「分享」按钮，与「继续/回茶地图」同级，玩家可跳过：
- **制茶结果**（`ResultView`，与「带去茶桌泡一杯」同排）：【分享制茶结果】
- **泡茶结果**（茶桌 `zhouBoAdvice` 区下方）：【分享泡茶结果】
- **茶席**（`TeaSeatView` 收尾 `ended` 阶段，与「离开茶席」同排）：【分享茶席】

点击 → 弹出结构化**分享卡**（DOM 渲染，移动端竖屏、截图友好，底部带《茶游记》品牌信息），并提供「保存到相册 / 系统分享 / 复制文案」等当前环境可用动作。

### 2.2 分享卡内容（复用现有数据，字段映射见 §1.3）
- 制茶卡示例：【武夷山·肉桂】「这一锅火候掌握得不错，桂皮香张扬，滋味浓烈，回甘明显。」（= `lastResult.comment`）+ 品质等级 + 火功标签 + 底部《茶游记》品牌。
- 泡茶卡：【茶】+【泡茶方式】+【周伯评价 `zhouBoAdvice.comment`】+【茶汤描述】。
- 茶席卡：【今日茶席】「武夷山的雨刚停，泡一盏岩茶，慢慢喝。」（场景+茶+NPC+氛围合成一句）+ 底部《茶游记》品牌。

### 2.3 奖励 + 防刷（六/七）—— 新建 `grantShareReward(type)`
- `gameStore` 新增 `grantShareReward(type: 'made'|'brewed'|'teaseat')`：
  - 读取 `player.flags` 中按**真实日期**（`new Date().toISOString().slice(0,10)`）的已领记录；日期变更自动清零。
  - 若该类型今日已领 → 静默 no-op（防刷：同一节点同内容不能反复 +20）。
  - 否则 `addCoins(20)` + 写 `flags['shareClaimed_'+type]=今日` + toast「📕 分享得茶钱 +20」。
  - 三种类型独立 → 一天最多 **60 茶钱**。
- 复用现有 `addCoins`（不新建货币）；与偶遇买茶 `-coins`、茶集市卖茶 `+coins` 同套货币。

### 2.4 平台回调与「不伪造」（八）
- **当前环境限制**：XHS 现以浏览器/webview 运行，无小红书 JSbridge；`navigator.share`（Web Share API）可拉起系统分享面板，但**无法可靠回传「已成功发帖到小红书」**。
- **方案（严格遵循八）**：
  1. 先做分享入口 + 分享卡（§2.1/2.2）；
  2. 预留 `confirmPostSuccess(type)` 接口（= 调 `grantShareReward(type)`），由未来平台发帖成功回调触发；
  3. **当前 webview 下，点击「分享」只生成卡片/拉起系统分享，绝不因此发 +20 茶钱**——奖励处于「已设计、未激活」状态；
  4. 本报告的 §3 明确写明平台能力限制；P2 接入真实发布能力后再点亮奖励。
- 不做「点分享即发钱」「伪造成功发帖」。

---

## 3. 平台能力限制（八）结论

- **当前 XHS 运行环境：浏览器 / 通用 webview，无小红书原生发帖成功回调。**
- 因此现阶段：
  - 分享卡与分享入口 = **可立即做**（纯前端，截图/系统分享即可）；
  - 「成功发帖 +20 茶钱」= **接口预留、暂不发放**，待小红书 JSbridge / 发帖成功回调解通后接入。
- 后续接入路线（P2）：通过小红书 H5 SDK 或宿主 App JSbridge 监听「发布成功」事件 → 调 `confirmPostSuccess(type)` → `grantShareReward`。在此之前，分享作为「生成内容 + 截图传播」的轻玩法存在，不影响主循环。
