## 0. 本轮最重要的一件事：把「资源系统」和「游历体验」分开

这是 V1.1 相对此前所有版本最关键的分水岭。

**旧倾向（要避免）**

```
采鲜叶 → 存鲜叶 → 消耗鲜叶 → 买鲜叶 → 卖茶 → 管理资源
```

顺着这条路走下去，游戏会不知不觉变成**茶叶经营游戏**：玩家关心的是库存、单价、周转，而不是那座山。

**V1.1 的定位**

```
采茶 = 一次旅行体验的一部分
```

玩家真正长期积累的不是资源，而是：

- 我亲手做过的**茶**
- 逐渐增长的**熟练度**
- 听来的**故事**
- 记下的**见闻**
- 指向下一座茶山的**线索**

> 一句话：**《茶游记》不是茶厂经营模拟器，是一场可以玩的中国茶山游历。**

## 1. 总体设计原则

### 1.1 继承 V0.3 的八条（不变）

| # | 原则 |
|---|---|
| P1 | 先问现实依据，再做游戏化；不要先写机制再找茶文化解释 |
| P2 | 现实提供骨架，游戏降低复杂度；简化必须保留真实工艺的**因果关系** |
| P3 | 内容分级 S 国标/地标 > A 国家级非遗/政府 > B 学术 > C 行业媒体/访谈 > D 营销（仅灵感，不作事实） |
| P4 | 前台不显示专业审评数字，只给「品质等级 + 自然语言 + 茶钱」 |
| P5 | 游戏自建经济体系，不复制现实茶价 |
| P6 | 知识是游历的副产品：先玩 → 看到变化 → NPC 说一句 → 好奇 → 漫画/手账补充 |
| P7 | 代码组件可以复用，**茶文化表达不能偷懒** |
| P8 | 真实，但好玩；不因为"真实"而不断增加工序 |

### 1.2 V1.1 新增四条

| # | 原则 | 说明 |
|---|---|---|
| **P9** | **资源系统 ≠ 游历体验** | 鲜叶不是长期库存；长期背包只存成茶、收藏、旅行记录。任何会催生"屯货/周转"心态的设计都要警惕 |
| **P10** | **70% 共享骨架 + 30% 茶类差异** | 不每种茶重做一套小游戏；差异用 Level 1/2/3 分级控制成本 |
| **P11** | **差异必须来自现实，分三档判断** | ① **现实中真的不同** → 可以做成玩法差异；② **现实中只是风格不同** → 做成轻量参数差异；③ **现实中没有依据** → **不要为了游戏硬造**。资料不足一律标记「待确认」 |
| **P12** | **失败也要有结果** | 失败不是"什么都没有"，而是"这批叶子没做成理想的茶"，仍产出成茶 |

### 1.3 三个必须分清的东西（全文档统一标记）

| 标记 | 含义 | 落点 |
|---|---|---|
| 【真实知识】 | 茶在现实世界中的事实 | 可进 `TeaFact` / 知识区 / 漫画 |
| 【游戏参数】 | 为可玩性设定的数值、难度、窗口、容错 | 只在 `gameProfile` / `StepParams`，**不得表述为事实** |
| 【游戏表达】 | NPC 语言、评价、比喻、幽默 | 只在 `TeaCopy(npcOpinion/gameHint/flavor)`，**不得进知识区** |

> 典型反例：「肉桂 = 香气型玩法」是【游戏表达】+【游戏参数】，**不是**【真实知识】，禁止写成"肉桂就是香气型茶"这类断言。

## 2. 鲜叶生命周期设计

### 2.1 核心定义

> **鲜叶是一轮制茶的原材料，不是长期库存资源。**

采茶的意义不是"积累资源"，而是**开启一轮制茶**。

### 2.2 生命周期

```
来到茶区
   ↓
找到阿秀
   ↓
阿秀带玩家上山采茶
   ↓
获得「本轮鲜叶」（隐藏档：good / normal / rough）
   ↓
进入制茶流程
   ↓
鲜叶进入工序（逐步转化为在制品）
   ↓
制茶完成（无论成败）
   ↓
鲜叶消失
   ↓
产出成茶 → 进入背包
```

**关键**：`鲜叶` 在制茶结束那一刻**必然消失**。它不会回到背包，也不会以任何数字形式存在。

### 2.3 玩家长期背包里有什么 / 没有什么

| 有 | 没有 |
|---|---|
| 成茶（按 茶种 × 品质 × 火功 堆叠） | ❌ 鲜叶 × 37 |
| 茶具 / 特殊道具（未来如需） | ❌ 鲜叶 × 82 |
| 收藏（茶、故事、漫画） | ❌ 任何形式的鲜叶库存 |
| 旅行记录（手账 / 线索 / 见闻） | ❌ 在制品囤积 |

### 2.4 代码现状对照（已符合新机制，无需改代码）

| 项 | 状态 |
|---|---|
| `Player.freshLeaves` | ✅ **已删除**（`types.ts` + `storage.ts` 默认）。它原是死字段，全文零读写 |
| 本轮鲜叶品质 | ✅ 已实现 `BasketQuality = 'good' \| 'normal' \| 'rough'`，随 `StepOutcome.basketQuality` 产出 |
| 采茶配置数据化 | ✅ 已实现 `TeaGameProfile.picking`（pickingMethod / targetMaturity / attemptCount / basketNeed / tolerance） |
| 采茶 → 制茶因果 | ✅ 已接通：`basketQuality` → `StepParams` → 焙火窗口 / 摇青区间 |
| 失败不扣鲜叶 | ✅ 本就成立：`finishMaking` 永远把成茶（含 fail 档）压入 `inventory` |

> 结论：**代码层已符合 V1.1 的鲜叶设计**，本节主要是把设计固化成文档，并修正 V0.3 中残留的旧表述（见第 16 节）。

### 2.5 不同茶区未来可有不同的采茶方式（保留）

`PickingConfig.pickingMethod` 已为跨茶区预留：

| 茶区 / 茶 | 采摘重点 | pickingMethod（建议） | 依据 |
|---|---|---|---|
| 武夷岩茶 | 开面采，取中开面成熟叶 | `'open-face'` | A（非遗）+ 资料库 §3.2 |
| 西湖龙井 | 细嫩采，芽叶（一芽一叶为主） | `'tender-bud'`（未来） | **待确认** |
| 凤凰单丛 | 待研究 | 待定 | **待确认** |
| 九曲红梅 / 茉莉花茶 | 待研究 | 待定 | **待确认** |

> 这是极好的跨茶区伏笔：同一个"采"的动作，在武夷山答案是"要开面"，到了杭州答案可能相反。这正是「每一座茶山都有自己的故事」最具体的落地。
> **但**：在补建对应茶区资料库之前，只允许占位，**不得凭想象写死规则**。

## 3. 失败机制重新设计

### 3.1 废弃旧机制

> ❌ 旧（V0.3 §15.3）：制茶失败 → **鲜叶 −1**
> **废弃理由**：如果玩家每次制茶前都能无成本地找阿秀重新采茶，那么"鲜叶 −1"不产生任何真实资源压力，只是个无意义的数字动画。

### 3.2 新理解

鲜叶本来就已经进入制作流程，无法退回。所以：

- **失败 = 这批鲜叶没有被做成理想的茶**
- 而不是：这批鲜叶被扣掉了

### 3.3 失败仍然产生结果

```
制茶成功              制茶失误
   ↓                     ↓
上品 / 良好 / 普通      失败品（低品质成茶）
   ↓                     ↓
    └────── 都进入背包 ──────┘
```

| 等级 | 玩家看到 | 说明 |
|---|---|---|
| 上品 | 「这锅茶，拿出去待客也不丢人。」 | 可卖 / 可赠 / 未来可斗茶 |
| 良好 | 「不错，已经有点样子了。」 | 可卖 / 可赠 |
| 普通 | 「能喝，但别急着拿去斗茶。」 | 可卖 / 自饮 |
| 失败 | 「这锅茶……自己喝吧。」 | 价值低（2–5 茶钱），可自泡、可留记录，**暂不适合斗茶** |

失败时**额外给一句可归因的原因**（沿用 V0.3 §15.2 的 FaultTag → 短句，如「火太急，香还没转出来。」），只说一个最主要的原因。

### 3.4 失败茶不是"没意义"

失败茶可以：

- ✅ 进入背包（它是"我做过的茶"，是经历）
- ✅ 自己泡来喝（形成"我尝尝自己做的失败品"的真实体验）
- ✅ 留在旅行记录（手账里的一条）
- ✅ 价值较低（2–5 茶钱）
- ⚠️ 暂时不适合斗茶（保留未来的成长空间）

> **设计意图**：玩家不会因为一次失误产生强烈挫败，而是产生"可惜了这篓叶子"的惋惜——惋惜是驱动重来的**情绪**，惩罚不是。

### 3.5 熟练度照涨

- 失败 +1，做成 +3，上品额外 +2（沿用 V0.3 §15.3，此部分不变）

## 4. 采茶 → 制茶完整循环

```
            茶山
              ↓
           找阿秀
              ↓
         上山采茶（一次旅行体验）
              ↓
       获得「本轮鲜叶」  ← 不是库存，是这一轮的原材料
              ↓
           开始制茶
              ↓
   ┌────────────────────────┐
   │      茶类独特工艺        │
   │  判断 / 操作 / 等待      │
   │  （Level 1 / 2 / 3）    │
   └────────────────────────┘
              ↓
            成茶（含失败品）
              ↓
          品质评价（自然语言）
              ↓
         茶叶进入背包（鲜叶消失）
              ↓
        泡茶 / 赠礼 / 未来斗茶
              ↓
          认识更多的人
              ↓
         获得下一站线索
              ↓
           前往下一座茶山
```

**这条链上最重要的一句**：鲜叶不进入长期库存。长期积累的是"我亲手做过的茶"。

### 4.1 采茶对制茶的影响（轻量、隐藏）

| 采茶表现 | 阿秀 / 岩伯的话 | 对后续制茶的影响【游戏参数】 |
|---|---|---|
| 好 | 「这批叶子不错。」 | 正常难度、正常容错 |
| 一般 | 「有几片叶子稍微老了些。」 | 容错略低（焙火窗口 −0.015） |
| 较差 | 「这篓叶子……得仔细做了。」 | 容错明显降低（焙火窗口 −0.04、摇青区间收窄 0.06） |

> 不引入"鲜叶品质 82 分"之类系统。玩家只通过 **NPC 评价 + 叶片视觉 + 简短反馈** 理解"我今天采的叶子会影响这一锅茶"。

## 5. 七种茶：真实工艺与玩法差异表

> **真实性声明**：武夷山三茶依据项目现有资料库（S/A/B 级）。
> **杭州 / 福州 / 潮州四茶**：当前仅基于通用茶学常识推演，**证据等级标注为「待补」**。在补建对应茶区资料库之前，这些工艺描述**不得进入 `knowledge` 数据**，只能作为设计草案。

### 5.1 武夷山 · 肉桂

| 项 | 内容 |
|---|---|
| 真实工艺 | 采摘（开面采）→ 倒青/萎凋 → 做青 → 炒青 → 初揉 → 复炒 → 复揉 → 焙火 |
| 共享部分 | 五步骨架、做青组件、炒揉组件、焙火组件、采茶、泡茶、结果卡、熟练度 |
| 最具辨识度工艺 | **做青（看青做青）+ 焙火（吃火）** |
| 玩家判断什么 | 摇青的力度与时机（看叶缘转朱砂红）；焙火落点稳不稳 |
| 游戏玩法 | 做青 3–4 轮（观察→摇→静置→判断）；焙火动态指针 ×5 |
| 失败方式 | 摇太急 / 火太急（香未转出） |
| 视觉反馈 | 叶缘转朱砂红；成茶色深、油润 |
| 需要新组件 | **否**（复用现有） |
| 真实性依据 | **A**（国家级非遗「武夷岩茶制作技艺」）、**S**（GB/T 18745） |
| 差异等级 | **Level 1** |

【游戏参数】焙火绿区偏右偏窄、炒青安全区窄、摇青力度中偏重。
【游戏表达】"香气很有存在感的茶。"——**这是游戏设计表达，不是专业事实断言**。

### 5.2 武夷山 · 水仙

| 项 | 内容 |
|---|---|
| 真实工艺 | 同肉桂（武夷岩茶同一工艺体系） |
| 最具辨识度工艺 | **做青状态的稳定**（把状态做稳） |
| 玩家判断什么 | 做青是否做到位、火候是否过急 |
| 游戏玩法 | 同骨架，参数更宽容 |
| 失败方式 | 青气还在 / 焙火过急 |
| 需要新组件 | **否** |
| 真实性依据 | **A / S**（同上） |
| 差异等级 | **Level 1** |

【游戏参数】容错略高、焙火绿区偏左偏宽（忌急火）、摇青力度中。
【游戏表达】"和肉桂不是一个路子，比较稳。"——希望玩家形成"这个茶特别讲究把状态做稳"的印象。

### 5.3 武夷山 · 大红袍

| 项 | 内容 |
|---|---|
| 真实工艺 | 同武夷岩茶体系 |
| 最具辨识度工艺 | **综合要求**：做青与焙火都要顾到，讲究"均匀" |
| 玩家判断什么 | 做青是否均匀、焙火是否居中 |
| 游戏玩法 | 同骨架；可引入"均匀度"判断（各轮表现的一致性） |
| 失败方式 | 任一环节偏颇 |
| 视觉反馈 | 条索紧结壮实稍扭曲（S 级特征） |
| 需要新组件 | **否**（"均匀度"可在现有 scoring 内加权重实现） |
| 真实性依据 | **S**（GB/T 18745 单列感官要求）、**A**（非遗项目名称含"大红袍"） |
| 差异等级 | **Level 1+**（介于 1 与 2 之间，先按 L1 实现，观察后再决定是否加"均匀度"交互） |

> ⚠️ **真实性红线**
> - ❌ 禁止使用「大红袍 = 肉桂 + 水仙」
> - ❌ 未经资料支持不断言「大红袍就是拼配茶」
> - ✅ 可采用的保守表述（V0.3 §10 已有）：**"大红袍是武夷岩茶的代表性名丛，拼配与独丛皆有"**；"大红袍不是一棵茶，是一类茶"
> - 解锁方式：**母树 / 游历线索内容触发**，不作等级门槛（M2）

### 5.4 杭州 · 西湖龙井（未来茶区，P2）

| 项 | 内容 |
|---|---|
| 真实工艺 | 摊放 → **青锅**（杀青 + 初步做形）→ 回潮 → **辉锅**（整形炒干）→ 分筛整理 |
| 共享部分 | 采茶框架、状态观察、结果卡、泡茶、NPC、熟练度、背篓 |
| 最具辨识度工艺 | **青锅 + 辉锅**（"龙井是在锅里做出来的"） |
| 十大手法 | 抓、抖、搭、拓、捺、推、扣、甩、磨、压 —— **不全做**，只取 1–2 个最有辨识度、最好玩的 |
| 玩家判断什么 | 锅中的**手法节奏与轻重**（做形），以及回潮后的辉锅时机 |
| 游戏玩法（Level 2） | 复用"控火"手感组件，但把判断重点从"火候"换成"**手法的轻重/节奏/路径**"：青锅一轮（定型）→ 回潮（等待观察）→ 辉锅一轮（整形，更慢更轻） |
| 失败方式 | 手法太重（扁碎）/ 火太高（黄焦）/ 辉锅不足（形松） |
| 视觉反馈 | 叶片由舒展 → **扁平挺直**；色泽由翠绿 → 糙米色 |
| 需要新组件 | **是**（锅中做形交互；`StepId` 需新增，见第 8 节） |
| 真实性依据 | **待补**（通用茶学常识；GB/T 18650 龙井茶；需补资料库 S/A/B） |
| 差异等级 | **Level 2** |
| 采茶差异 | 细嫩采（芽叶），与武夷开面采**相反** —— 强伏笔（见 2.5） |

**玩法三问**
- **现实是什么？** 龙井的形（扁、平、光滑）是**在锅里用手做出来的**，青锅定型、辉锅整形。
- **为什么重要？** 外形是龙井辨识度最高的特征之一，手法轻重直接决定成条与完整度。
- **游戏怎么简化？** 不做十种手法，只做"**轻重 + 节奏**"两个维度；玩家在锅中控制手法轨迹，看叶片逐渐变扁挺直。

### 5.5 杭州 · 九曲红梅（未来茶区，P2）

| 项 | 内容 |
|---|---|
| 真实工艺 | 萎凋 → 揉捻 → **发酵** → 干燥 |
| 共享部分 | 萎凋/摊放、揉捻、结果卡、泡茶 |
| 最具辨识度工艺 | **发酵** |
| 玩家判断什么 | 观察茶叶状态变化，**判断停止发酵的时机** |
| 游戏玩法（Level 2） | **"等待 + 判断"型**：叶色/香气持续变化，玩家在合适窗口主动停止。与做青（摇+等+再摇）不同，这里是**单向推进、只判一次停止点** |
| 失败方式 | 发酵不足（青气重）/ 发酵过度（叶底暗、香气钝） |
| 视觉反馈 | 叶色由青绿 → **铜红**；青草气 → 甜香 |
| 需要新组件 | **是**（发酵组件；`StepId` 已预留 `fermentation`，见第 8 节） |
| 真实性依据 | **待补**（通用茶学常识；需补资料库） |
| 差异等级 | **Level 2** |

**玩法三问**
- **现实是什么？** 红茶发酵是酶促氧化过程，叶色与香气随时间变化，发酵程度决定品质风格。
- **为什么重要？** 发酵不足或过度都会明显损害品质，且不可逆——这是红茶最核心的判断点。
- **游戏怎么简化？** 用"持续变化的状态 + 一次停止判断"表达；不出现温度/湿度/分钟数，只给叶色与香气的可视变化 + NPC 提示。

### 5.6 福州 · 茉莉花茶（未来茶区，P2）

| 项 | 内容 |
|---|---|
| 真实工艺 | 茶坯（多为绿茶）→ **窨制**（拌和鲜花）→ **通花**（散热）→ **起花**（筛出花渣）→ 复火 → **再窨**（可多次）→ 提花 |
| 共享部分 | 结果卡、泡茶、NPC、熟练度、背篓 |
| 最具辨识度工艺 | **窨制**：把花香一层一层做进茶里 |
| 玩家判断什么 | 什么时候**通花**、什么时候**起花**、要不要**再窨一次** |
| 游戏玩法（Level 3） | 茶 + 花 → 窨制（等待/观察温度与香气）→ 通花（时机操作）→ 起花（筛分）→ 复火 → **可再次窨制**（多轮累积，越窨越足，但风险也累积） |
| 失败方式 | 通花不及时（闷坏/热损）/ 起花不净（花渣残留）/ 窨次与火候失衡（香薄或失真） |
| 视觉反馈 | 茶堆温度（热气/色温）、花瓣由鲜挺 → 萎谢、香气浓度视觉化（分层累积） |
| 需要新组件 | **必须新增**（`StepId` 新增 `scenting`，含通花/起花子状态） |
| 真实性依据 | **待补**（通用茶学常识；GH/T 1071 茉莉花茶；需补资料库） |
| 差异等级 | **Level 3（唯一）** |

> ⚠️ 真实性注意：「几窨一提」的具体表述**不作硬知识**，只能作为 NPC 口语 / 游戏表达。

**玩法三问**
- **现实是什么？** 茉莉花茶靠鲜花吐香、茶坯吸香，通过多次窨制把花香做进茶里；通花是为了散热防止闷坏，起花是筛出花渣。
- **为什么重要？** 窨制是茉莉花茶区别于其他茶类的根本工艺，"香"来自花而不是茶本身。
- **游戏怎么简化？** 做成**可重复的轮次循环**：每轮 = 窨 → 通花 → 起花，玩家决定是否再来一轮；用花瓣状态与香气层数的视觉表达替代温度与时间数字。

### 5.7 潮州 · 凤凰单丛（未来茶区，P2）

| 项 | 内容 |
|---|---|
| 真实工艺 | 晒青 → 凉青 → **做青（碰青/浪菜）** → 杀青 → 揉捻 → 烘焙 |
| 与武夷做青的关系 | **同属乌龙，做青逻辑高度相似**；差异主要在手法名称（碰青/浪菜 vs 摇青）、单次做青程度与节奏 |
| 最具辨识度工艺 | 做青（反复做青） |
| 玩家判断什么 | 做青程度（与武夷相似，但节奏与判断窗口不同） |
| 游戏玩法（Level 2） | **复用做青组件**，通过 **参数 + 节奏 + 判断窗口 + 反馈文本** 形成差异 |

## 6. 差异化等级：Level 1 / 2 / 3

| 等级 | 定义 | 成本 | 适用 |
|---|---|---|---|
| **Level 1 参数差异** | 同一玩法，不同难度 / 节奏 / 容错 / 判断窗口 | 极低 | 肉桂、水仙、大红袍 |
| **Level 2 交互差异** | 同一工艺组件，不同玩家操作方式 | 中 | 西湖龙井（锅中做形）、九曲红梅（发酵判断）、凤凰单丛（做青复用+节奏） |
| **Level 3 独有玩法** | 只有该类茶真正存在的独特工艺，才开发新组件 | 高 | 茉莉花茶（窨制） |

**判定规则**：
- 现实工艺逻辑高度相似 → **复用组件**，用参数与反馈制造差异（凤凰单丛）
- 现实中确实存在其他茶类没有的工艺 → 才做 Level 3（茉莉窨制）
- **不为"看起来不一样"而造新玩法**

> **当前阶段的正确选择：武夷山三茶保持 Level 1，不急于进 L2。**
> 第一优先级是把「采茶 → 制茶 → 泡茶 → 品茶 → 茶集市」这个完整闭环跑通。
> 等闭环真的能玩了，再用一句"我玩肉桂和水仙的时候，真的能感觉到区别吗？"来检验——**如果不能，再进 L2**。
> 三茶同属武夷岩茶，现实中工艺骨架相同；**强行造三种玩法反而违背 P11**（不为游戏硬造差异）。

| 3 | **窨制组件** | 茉莉花茶 | 需新增 `scenting` | **L3** | 窨 → 通花 → 起花 → 复火 → 可再窨；含子状态机 |

> ⚠️ **重要澄清（架构预留 ≠ 玩法可套用）**
>
> `StepId` 已预留 `withering / fixation / rolling / drying / fermentation`，这只解决了**数据层挂载**的问题，
> **绝不意味着玩法可以直接套用**。例如 `fermentation` 这个 StepId 已存在，并不代表九曲红梅能直接套用某个现成的"发酵小游戏"——它仍然需要**新的交互组件与规则**。
>
> 未来真正需要新增的，往往**不是很多个 StepId，而是「已有 StepId + 不同的交互组件 / 规则」**：
>
> | 茶 | 核心工艺 | StepId | 真正要做的事 |
> |---|---|---|---|
> | 武夷岩茶 | 做青 | `zuoqing`（已有） | 现有组件，继续打磨参数 |
> | 凤凰单丛 | 做青（节奏/手法不同） | `zuoqing`（复用） | **同一 StepId，换参数 + 节奏 + 反馈** |
> | 九曲红梅 | 发酵 | `fermentation`（已预留） | **需新建"等待 + 判断"交互组件** |
> | 西湖龙井 | 锅炒/做形 | 需新增 | **需新建锅中做形组件** |
> | 茉莉花茶 | 窨制 | 需新增 `scenting` | **需新建窨制组件**（含通花/起花子状态） |
>
> 这正好落在 **70% 共用交互组件 + 30% 茶类特色玩法** 的分工上：共享的是骨架与交互原语，差异的是每类茶真正的核心操作。

## 11. 泡茶玩法与制茶玩法的衔接

### 11.1 当前已实现（拖拽版）

温杯 → 倒掉温杯水 → 投茶 → 注水 → 揭盖闻香 → 出汤 → 品饮。
茶壶可拖动、可见水流、可揭盖、可见茶叶、可闻香、可倾斜出汤。**轻量模拟，不做物理引擎。**

### 11.2 与制茶统一操作语言

| 环节 | 观察 → 操作 → 判断 → 反馈 |
|---|---|
| 焙火（制茶） | 看火 → 判断 → 点击落火 |
| 出汤（泡茶） | 看汤 → 判断 → 点击出汤 |

让玩家逐渐形成《茶游记》自己的操作语言：**看 → 判断 → 点**。

### 11.3 未来可作差异（轻量）

不同茶在泡茶环节的表现差异（如肉桂第一泡香冲、大红袍杯底留香）可作为**泡茶彩蛋**，均属【游戏表达】，不作硬知识。

| P2-4 | 福州资料库 + **Level 3 窨制组件**（茉莉花茶） | 资料库 |
| P2-5 | 潮州凤凰单丛（复用做青，L2） | 资料库 |
| P2-6 | 集市 / 斗茶 / 中国茶山地图 | 第二座山上线后 |

### 14.4 开发顺序：先闭环，再差异

```text
L1  共享制茶框架 + 难度 / 容错 / 反馈差异
        ↓   先让游戏完整可玩
L2  加入茶类真正不同的关键操作
        ↓   让玩家明显感到"这是另一种茶"
L3  加入更深的茶类特色机制
        ↓   形成真正的茶区 / 茶类差异
```

> **Q5（"不同茶是否玩起来不一样"）当前不急着解决。** 三茶保持 L1 完全够用；先把闭环跑通，再决定要不要进 L2。

> **边界警告（沿用 V0.3）**：第二座茶山在补建资料库之前，一切玩法设计都只是草案。先做一座山，再做整个中国。

## 15. 产品逻辑自检（Q1–Q8）

**Q1：玩家制茶失败，到底失去了什么？**
失去的是**"这一篓叶子的可能性"**——它本来可能被做成上品。但玩家没有失去任何资源（因为鲜叶从来不是资源），仍然得到一批属于自己的失败茶，可以自泡、留在记录里。惋惜感来自"可惜了这篓叶子"，而非"系统扣了我一个东西"。

**Q2：下一次想重新制茶，需要做什么？**
回到茶山，找阿秀，**再上山采一篓**。这不是"补资源"，而是**又一次上山**——会再看到那片茶园、再听阿秀说两句话。重来的成本是"一段体验"，不是"一份库存"。

**Q3：为什么玩家愿意重新去采茶？**
三个理由叠加：① 采茶本身是旅行体验（山、人、对话），不是苦工；② 想做出更好的茶；③ 熟练度与故事在累积。**没有任何一条依赖"资源压力"**。

**Q4：采茶和制茶之间是否真的形成因果关系？**
是。`basketQuality`（好/一般/较差）会真实改变后续焙火窗口与摇青区间。但它是**隐藏档**：玩家看不到数字，只通过阿秀那句"有几片叶子稍微老了些"、以及后续确实"更不好控"的手感来感知。

**Q5：不同茶叶是否真的"玩起来不一样"？**
**目前还不够，但这是当前阶段的正确选择，不急于解决。**
武夷山三茶都是 **Level 1 参数差异**：共享核心操作，只在容错、难度、反馈、部分参数上产生差异。玩家能感到"难易不同"，但操作语言相同。
**处置**：第一优先级是把「采茶 → 制茶 → 泡茶 → 品茶 → 茶集市」完整闭环跑通；等闭环真的能玩了，再用"我玩肉桂和水仙的时候，真的能感觉到区别吗？"来检验——**如果不能，再进 L2**。
**不越界**：三茶同属武夷岩茶，现实工艺骨架相同，**不为差异化而虚构不存在的工艺**。后续 L2/L3 再逐步增加真正有茶类依据的差异化玩法。

**Q6：这种差异是否来自真实工艺？**
设计上强制要求来自真实工艺（P11）。但必须承认：**杭州/福州/潮州四茶目前只有通用茶学常识支撑，尚未补 S/A/B 级来源**。在补证前它们只是草案，不得进知识系统。

**Q7：是否存在不必要的资源、数值和系统复杂度？**
已清理：鲜叶库存已删、熟练度不拆分、不显示审评数字、不显示熟练度数字、采茶不用分数。当前系统只保留"成茶 + 熟练度 + 故事/线索"三条长期线。

**Q8：玩完以后，是"记住了一堆知识"，还是"真的体验过一座茶山"？**
目标答案是后者。判断标准：玩家事后说得出的应该是"我在武夷山采了一篓叶子、看着叶缘转成朱砂红、火候没控住、可惜了"，而不是"武夷岩茶有十六道工序"。
